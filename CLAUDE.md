# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Unity **6000.6.5f1** project (URP 3D template): a multiplayer block-world game in the spirit of *Eco*: the server simulates an ecosystem (plants that grow, spread and die) that players affect. Current state: voxel world, dedicated-server multiplayer, and a first plant simulation. One scene (`Assets/Scenes/SampleScene.unity`, the only scene in the build settings). `Assets/TutorialInfo/` and `Assets/Readme.asset` are leftovers from the Unity template, not project code.

## Architecture

Code is split into assemblies so that a future dedicated server can run the world without rendering:

- `Assets/Scripts/Voxel.Core` — blocks, chunks, world, generation, collision, raycast. **Pure C#: the asmdef sets `noEngineReferences`, so `UnityEngine` is unavailable here.** Vectors are `System.Numerics.Vector3`; positions are `BlockPos` / `ChunkCoord`.
- `Assets/Scripts/Eco.Sim` — the ecosystem simulation: soil fertility, plants, species rules, simulation clock, save format. **Pure C# as well (`noEngineReferences`), depends only on `Voxel.Core`.**
- `Assets/Scripts/Voxel.Client` — meshing, rendering, input, player, and for now the session/network code. Converts vectors at the boundary with `ToNumerics()` / `ToUnity()`.
- `Assets/Tests/Voxel.Core.Tests`, `Assets/Tests/Eco.Sim.Tests` — EditMode tests for the two pure assemblies.

Key rules:

- `World.SetBlock` is the only way gameplay code changes a block. It marks the chunk modified and raises `World.BlockChanged`, which remeshing listens to (networking and saving will hook in the same way). `Chunk.Set` is a raw write for generators only.
- `World.IsSolid` treats everything outside the world's sides and bottom as solid (keeps players in, culls unseen faces); `World.GetBlock` returns air there. **Solid, opaque and replaceable are separate** (`Blocks`): water is none of solid (players and rays pass through it, it cannot be broken), opaque (faces next to it are drawn, so a lake's bed shows; use `World.IsOpaque` for face culling) or occupied (a placed block pushes it out, `Blocks.IsReplaceable`). Use `IsSolid` for collision, support and aiming. `World.GetSurfaceHeight` is the top of the solid ground (under water, the bed); `World.GetTopHeight` counts water (what is seen from above). A player never sets water (`BlockEditRules`).
- A block is a `ushort`: low 12 bits are the type, high 4 bits the orientation. Compare types through `Blocks.TypeOf(block)`, never the raw value.
- `WorldSave` stores a header (seed, generator version, dimensions) plus **only the modified chunks**; untouched chunks are regenerated on load. Any change to what a generator produces must bump `IChunkGenerator.Version`, which makes older saves fail to load instead of loading corrupted. `ChunkSerializer` (run-length encoded) is meant to be reused as the network chunk format.
- A persistent world is loaded from `world.dat` in the server's data folder and written back by `VoxelWorld.Save` and `Unload`. A save whose seed or dimensions differ from the inspector settings, or that fails to load, is ignored with a warning and overwritten on exit. Delete the file to reset the world.
- Terrain comes from `TerrainGenerator` (version 5: plains, hills, bare-rock massifs from `ReliefHeight`, relief below 64 blocks, plus water, rocks and caves). **Server and clients each generate the same world from the seed, so generation must be bit-identical on every machine**: it uses only integer math (`IntNoise`, fixed point with `IntNoise.One` = 1; `IntNoise.TurnedFractal` blends a grid turned by about 53° so that value noise leaves no straight valleys), never floats, `System.Random` or anything order-dependent. `TerrainGeneratorTests` pins reference heights and a world fingerprint; if they change, the generator's output changed and `TerrainGenerator.Version` must be bumped (old saves are then refused, and clients on another version are turned away). `IChunkGenerator.Prepare(seed, sizeX, sizeZ)` is called by `World.Generate` before any chunk: what depends on the whole world is worked out there.
- **Water** comes from `Landscape` (`Voxel.Core`, `Landscape.For(seed, sizeX, sizeZ)`, the last one cached): the relief lowered into lake basins and, along the west edge, under a sea (`SeaLevel` = 20, the plains' height, so shores are flush); a **priority flood** from the world's edges held at sea level fills each hollow to its rim (lakes; those under 150 columns are filled in as land instead); a second flood over the final relief, with smooth noise of up to 2.5 blocks so that water wanders on flat land, gives each column the neighbour it drains to, and **rivers** are carved where the catchment exceeds 3,000 columns (3 wide above 15,000, 2 deep above 40,000), flush with the lowest ground around so water never stands above its banks (`LandscapeTests.Water_IsHeldByItsBanks`). Ice tops water where the climate is cold. About 17 % of the land is water.
- **Geology** (`Landscape.LayGeology`, `Landscape.Column`, `TerrainGenerator.RockAt` / `OreAt`, version 4): from the bottom, bedrock (y = 0, ragged on y = 1–2, unbreakable: `Blocks.IsBreakable`), the granite basement (`Blocks.Stone` is granite), then a cover rock 8–24 blocks thick chosen by region: limestone where it is mild, sandstone where it is dry and warm, slate where it is cold, basalt in volcanic provinces (about one in ten, zones of 256 blocks). Above height 40 the cover thins by 3 blocks per block, so the massifs' heights show granite. Marble is a 2-block band at the base of thin limestone (≤ 12) on ground ≥ 30. The top block and the 3 under it: grass on dirt; snow on dirt where it is coldest or high and cool (also on bare rock); sand on sand in dry warm regions and on beaches within 2 of a lake or the sea; under water gravel (rivers), clay (lakes) or sand (sea). Ores are decided per block from an integer hash: cells of 4 × 4 × 4 hold ore with a chance by host rock and depth (sedimentary: coal, flint in limestone near the surface, rock salt in sandstone; granite: copper, tin only in cold regions, gold below 25 blocks; basalt: iron; iron a little everywhere), then 3 blocks in 4 of the cell are ore. In a 512 world that is about 8 ‰ coal, 7 ‰ iron, 4 ‰ copper of the solid blocks, gold under 1 ‰ (`GeologyTests`). Before plant species had climates, deserts and snow were bare: with them the food chain was re-checked over 450 days on two seeds in a 512 world (rabbits 476–883, foxes 92–151). It takes about 0.6 s for a 1024 × 1024 world, on the server and on each client. **Water does not flow**, except that the server fills holes (`WaterFill`, called by `WorldSync.TryApplyEdit` when a block is broken): a block that becomes empty with water beside or above it takes water, and so does the empty space joined to it sideways or below, never above; a space over 4,096 blocks is open land and is left dry. The server sets those blocks 64 per frame.
- **Caves** (`Caves`, `Voxel.Core`, built by `Landscape` with the rest, carved by `TerrainGenerator.Generate` into each chunk with `Caves.Carve`, version 5): hollows (rounded volumes: a tunnel's section, a cavern's wide low dome with a flatter floor) strung along tunnels that wander like worms, one block per step, turning and tilting a little each step (angles in whole degrees, sines from Bhaskara's integer formula, positions in 1/16 block, an xorshift seeded per region: no floating point). Each region of 32 × 32 columns may hold a system (70 % in limestone, the karst, 45 % in basalt, 35 % elsewhere): 30 % open on the surface (entrances, on dry land only), tunnels fork, some widen into caverns (more in limestone), caverns keep 4 blocks of rock over them, and in basalt half the systems are lava tubes (round, flat-floored, a few blocks under the ground, as long as they stay in basalt). Nothing is carved at y ≤ 2 nor within 4 blocks under surface water or within 2 columns of it, so lakes, rivers and the sea never stand over a void. Some caverns hold a **cave lake**: water up to a block or two above their floor in every hollow block joined to them below that level, found in a box around the cavern; a lake that would reach the open air, the box's sides or 4,000 blocks is not made, so cave water is always held by rock (`CavesTests`). In a 512 world: about 20,000 hollows, 70–85 caverns, 35–40 entrances, 15–20 lakes, 2.4 % of the underground volume; about 20 ms (50 ms for 1024 × 1024). Caves are dark (sky light), and plants and animals keep to the surface: no plant grows on bare rock, animals never drop more than 3 blocks.
- Water is drawn as a second submesh of each chunk (`ChunkMesher.WaterSubmesh`) with `Assets/Materials/Water.mat` (the blocks' shader `ECO/Blocks` in transparent mode, so it darkens with the sky light like the blocks; no shadow casting, no depth), its surface a little below the top of the block under air. The player swims (`PlayerController`): with the block at 0.4 above the feet in water, gravity is 30 %, sinking at most 2 blocks/s, Space swims up at 3, moving at 60 %; swimming against a bank (`MoveResult.HitWall`) with Space and a direction held gives the push of a jump, since swimming up alone never lifts the feet a block above the surface, the height of a flush bank; with the eyes under water, the scene's fog turns blue and short (given back when the eyes come out or the controller stops). Land animals never enter water nor walk on a bed (`AnimalMoves.GroundOf`); water animals have their own habitats (below); a plant needs air, not water, at its base.
- **Climate**: `Geography` (`Voxel.Core`, `World.Geography`, worked out once from the seed and size) holds temperature and humidity on a grid of 8 × 8-column cells, in fixed point, under the same bit-identical rules as the terrain, so nothing is sent. Temperature: hot in the south (z = 0), cold in the north, zones of about 256 blocks, colder with altitude. Humidity: its own zones, multiplied by the air's moisture as a west wind carries it row by row: rising ground makes it rain (wet windward slopes), the land past a massif is dry (rain shadow), and rows are blurred together; land near water is wetter. `TemperatureAt` / `HumidityAt` blend between cell centres. `Geography.Create(seed, size)` is the one `Landscape` computes over its ground and water (as generated, never the edited world); tests build it over any relief with the other overload. `GeographyTests` pins reference values; changing the climate changes fertility and grass colour on every machine. It takes about 10 ms for a 1024 × 1024 world. World roadmap: 1 climate, 2 water, 3 geology, 4 sky light with day and night, 5 caves, 6 plant species, 7 land animals per climate, 8 carrion, 9 water animals and 10 birds are done (the world roadmap is complete). Steps 2, 3 and 5 changed generation (each bumped `TerrainGenerator.Version`, now 5, and reset worlds); light did not.
- The player uses voxel collision (`VoxelCollision.Move`), not Unity physics; chunks have no `MeshCollider`. `transform.position` of the player is the centre of its feet.
- `VoxelWorld.World` only exists during a session; it is `null` in the menu. The host gets it from `VoxelWorld.LoadPersistent` (called by `GameSession` right before starting the network); a client gets an empty world from `VoxelWorld.CreateRemote` when the server's world info arrives. `GameSession` unloads it when the session stops.
- **Gameplay code reads the world through `WorldSync.World`**, which stays `null` until the world is fully available on this machine (on a client, until every chunk has arrived). The local player does not simulate before that.
- **Players never call `World.SetBlock` directly: they call `WorldSync.RequestSetBlock`.** The server validates every request (`BlockEditRules` in `Voxel.Core`, plus "not inside a player") and broadcasts accepted changes; a client applies its own request immediately and the server sends back the real block if it refuses.

Ecosystem simulation (`Eco.Sim`, run by the server only):

- **`Ecosystem.Step()` is the only thing that advances the simulation, and it must stay deterministic**: no real time, no `UnityEngine`, no `System.Random` (use the ecosystem's `SimRandom`, whose state is saved), and plants are processed in list order. Tests rely on "same seed + same calls = same forest", including across a save and reload.
- Time acceleration never changes what a step does: `SimClock` only decides *how many* steps to run (one step = 10 game minutes; at speed 1 that is 10 real seconds). Do not scale step effects by a delta time, and never use `Time.timeScale`. `EcosystemSync.Update` runs the due steps within an 8 ms budget per frame; steps queued by "advance N days" always run, backlog caused by the multiplier is dropped.
- Soil fertility lives on a coarse grid (`Ecosystem.CellSize` = 4×4 block columns per cell). Each cell regenerates toward its own capacity: 60 % from the climate (`Ecosystem.ClimateRichness`: wetness most, then mildness) and 40 % from smooth rich and poor patches, recomputed at construction (not saved). With it the food chain was re-checked over 500 days on two seeds on a 512 × 512 world (rabbits 1,090–1,450, foxes 178–222, the same density as before). Plants draw it down; below a species' `MinFertility` seeds do not germinate and plants starve.
- A block column holds at most one plant. `Species.Spacing` only applies between plants of the same species. A plant dies, at the next step, if the block under it is no longer dirt or grass or if a block is placed where it stands. This is not re-read every step: the ecosystem listens to `World.BlockChanged` and only rechecks plants in columns that changed, so **a block changed without `World.SetBlock` would never uproot a plant**.
- `Step` cost is what limits time acceleration (about 5 ms for 80,000 plants in the Editor). Plants live in an array sorted by id, looked up by binary search; keep the per-plant work in `Live` free of dictionary lookups and block reads.
- Plants are records, not GameObjects and not `NetworkObject`s. They have no collision: players walk through them.
- Species are data: `SpeciesAsset` (ScriptableObject in `Assets/Species`, durations in game days, plus the meshes and materials to draw) converted to `Eco.Sim.Species`. **Plants reference their species by index in `EcosystemSync.speciesAssets`**, so reordering or renaming species makes `ecosystem.dat` fail to load (a fresh ecosystem then replaces it). The save also records the world's seed and generator version and is refused on any other terrain, since plant positions only make sense on the terrain they grew on. Balance lives in these assets.
- **Plant species live by climate** (`Species.Suitability`, `SpeciesAsset` "Climate and ground"): each has an ideal range of warmth and of wetness (0 to 1, Geography's temperature and humidity) and a tolerance past them; the product of both fits, the plant's **vigour**, is how often its seeds take and how fast it grows (`Plant.Vigour`, from `Ecosystem.VigourAt`, worked out per fertility cell at construction; not saved, recomputed on load). Each also has the grounds it grows on (`Grounds`: grass and dirt by default; pines also snow, acacias and dry grass also sand, cacti only sand) and may need water beside it (`NeedsWater`: reeds). The ten species, in `EcosystemSync.speciesAssets` order: `Oak` (mild, wet, rich soil), `Bush` (wide range), `Birch` (cool), `Pine` (cold, snow), `Acacia` (hot, fairly dry), `Poplar` (mild, wettest), `TallGrass` (wide range), `DryGrass` (warm, dry), `Cactus` (hot, driest, sand), `Reeds` (water's edge). Rabbits eat bushes and tall grass. Over 500 days on two seeds in a 512 world (about 41,000 plants, 2 ms per step), every species holds and each climate has its own cover: pine and birch where it is cold, dry grass, acacias and cacti where it is warm and dry, oaks, poplars and bushes where it is warm and wet, a mix in between; rabbits 760–950, foxes 100–150. **Dense forests**: the forest trees (oak, birch, pine, poplar) were then given spacing 2, about half their fertility use and more seeds (acacias stay sparse, spacing 4), because the soil fed only about 3 grown trees per fertility cell: on seed 1 by day 100 there are about 50,000 trees among 62,000 plants (19 % of columns in the median 16 × 16 region, 40–60 % in the densest; mild wet land becomes continuous forest, dry land stays open), bushes fell from 3,500 to 1,700, and a step costs about 4.2–5 ms in the Editor (2.9–3 before). Over 500 days on seeds 1 and 2 in a 512 world (about 63,000–64,000 plants, 49,000–52,000 of them trees) every species holds, without extinction (from day 100, seed 1 / seed 2: rabbits 298–480 / 250–437, hares 358–472 / 324–426, jerboas 122–204 / 150–227, deer 46–111 / 30–141, reindeer 9–49 / 7–60, gazelles 5–51 / 15–104, foxes 55–86 / 46–99, wolves 11–32 / 24–66, bears 5–29 / 17–31, jackals 12–41 / 14–58, fish 394–650 / 1,308–2,049, ducks 127–283 / 154–354, herons 7–17 / 8–24, otters 9–16 / 10–22, crows 25–89 / 31–85, vultures 41–73 / 56–84, sparrows 42–73 / 44–87). Reindeer peak lower than before (60 at most), bears touched 5 on seed 1, and fish stay low on seed 1; none of these was compared with a run of the old values on the same seed.
- `EcosystemSync` mirrors `WorldSync`: named messages, server-authoritative. A joining player receives the existing plants in batches of 500 per network tick (resuming by plant id, which stays correct while plants are born and die), and every player gets, once per network tick, only the final state of plants that changed (a plant's growth is sent as one of `Plant.StageCount` stages, not continuously). Felling is requested with `EcosystemSync.RequestFell` and validated for reach by the server; clients predict it and get the plant back if refused.
- Animals (`Ecosystem.Animals.cs`) follow the same rules as plants: records in an array sorted by id, one animal per block column, all behaviour inside `Step` with the shared `SimRandom`. Each step an animal gets hungrier, seeks food when hungry (herbivores graze plants from the next column, which lose half their growth: a plant left with less than 0.1 dies, so browsed saplings die; a plant is only eaten from growth 0.25 and if no taller than the animal's `ReachHeight`, so deer browse young trees, not grown ones; predators catch prey next to them, half as often when the prey is taller than the hunter), otherwise joins the nearest of its kind if it is a herd animal (`Herd`) or wanders toward the best of three random places for its climate, and may breed when well fed, less often where its climate suits it less.
- **Animals collide with blocks** through `AnimalMoves` (`Eco.Sim`): they walk up to `MoveRange` columns per step, one column at a time in eight directions, climbing at most 1 block and dropping at most 3, never cutting diagonally past a block's corner, sidestepping obstacles but never turning back. So a wall two blocks high stops them (fences work). The server also refuses to place a block inside an animal (`Ecosystem.IsAnimalInside`, checked in `WorldSync`). The client's `AnimalViews` re-walks the same rules on its own world (only start and end positions are sent) so the displayed animal follows the ground and goes around walls; it cannot know the occupancy detours, which are harmless. Changing these rules changes the food chain balance: it was re-checked over 500 days on two seeds after they were introduced (rabbits 250–450, foxes 34–68 on a 256 × 256 world). Species are `AnimalSpeciesAsset`s (diet given as references to other species assets, resolved to indices by `EcosystemSync`).
- **Two rules keep the food chain alive; removing either brings back boom-and-bust or extinction**: `TerritoryRange` / `MaxNeighbours` stop an animal breeding when enough of its kind are nearby (without it herbivores multiply until they strip the plants, which then cannot reseed), and `MinDensity` lets newcomers arrive, at random columns whose climate suits the species, when it falls below a floor (counted over the land whose climate suits it). The current values were chosen by simulating 500 days on several seeds; re-run such a simulation before changing them (an `Ecosystem` can be built and stepped directly from editor code, no Play mode needed).
- **Animal species live by climate** like plants (`AnimalSpecies.Suitability`, `AnimalSpeciesAsset` "Climate", per fertility cell: `Ecosystem.AnimalVigourAt`). The ten species, in `EcosystemSync.animalAssets` order (indices are saved): `Rabbit` and `Fox` (mild), `Deer` (mild, wet; herd; grass, bushes, young oaks, birches and poplars), `Reindeer` (cold; herd; grass, bushes, young birches and pines), `Wolf` (cold to mild; pack; deer, reindeer, rabbits, hares), `Bear` (cool forests; bushes, hares, rabbits), `Gazelle` (hot, dry; herd; dry and tall grass, young acacias), `Jackal` (hot; jerboas, gazelles, rabbits), `SnowHare` (cold; grass, bushes, young birches), `Jerboa` (hot, driest; dry grass, young cacti). Over 500 days on two seeds in a 512 world every species holds, without extinction (from day 100: rabbits 200–580, hares 370–475, jerboas 110–215, deer 60–165, reindeer 9–135, gazelles 6–70, foxes 18–68, wolves 9–57, bears 9–36, jackals 9–48; about 36,000 plants, 2.3 ms per step).
- **Water animals**: each animal species has a habitat (`AnimalSpecies.Habitat`, `AnimalHabitat`), which decides where it can stand in a column (`AnimalMoves.GroundFor`, from the column's top, whether water lies on it and its bed; the same rules on the server, cached per column in `Ecosystem.ReadColumn`, and in `AnimalViews`' display routes): `Land` (on the ground, never on water), `Water` (in the topmost water block, never on land: `Fish`), `Shore` (on land, or afloat on the water's surface: `Duck`, `Otter`; drawn `AnimalViews.FloatingDraft` below the block's top when above water) and `Wader` (on land, or on the bed of water at most `AnimalMoves.MaxWadingDepth` = 2 deep: `Heron`). Moves, births, settling and the per-step ground check all use the species' habitat; an animal left where it cannot live (a fish whose water is filled in, a deer under water) dies, and one that dies in water leaves no carcass. Shore animals and waders like places beside water (`HabitatFit`: away from it a place counts 0.2), when wandering and when settling, or they starve far from the fish. A species that eats nothing the simulation knows (`!AnimalSpecies.EatsSomething`: fish) never gets hungry, so it can keep breeding. Fish live in schools (herd, territory 8 with up to 12 neighbours) everywhere; herons and otters eat fish, foxes ducks, bears also fish; ducks graze tall grass and reeds. The four models come from `AnimalModelBuilder` (a bird layout for the duck and the heron, a fish layout, the otter a quadruped). Over 500 days on two seeds in a 512 world every species holds (from day 100: fish 680–1,800, ducks 100–390, herons 6–17 and otters 10–24, rare predators, at times at their floor; the land species as before, deer 33–131, wolves 12–46; about 33,000–35,000 plants and 330 carcasses, 2.6 ms per step). `WaterAnimalTests` cover each habitat's ground, fish kept to water, a fish whose pond is filled in, ducks on water and land, herons in shallow water only, and a heron's catch.
- **Birds**: habitat `Air` (`AnimalMoves.GroundFor`: on top of anything, ground or water), and moves with `flies` (`AnimalMoves.TryNextStep` / `CanEnter`): no climbing or dropping limit, so walls and cliffs do not stop them, nor fences. A bird that eats plants with `AnimalSpecies.SpreadsSeeds` keeps a seed of the plant it ate (`Animal.CarriedSeed`, the species index plus one, saved in `ecosystem.dat` format 5) and each step lets it fall with a chance of 1 in 4 where it now is (`DropSeed` → `TryPlant`, so only where that plant could grow): birds carry bushes and grass far from their parents. The three species: `Crow` (cold to mild; flocks; carrion and bushes, spreads seeds), `Vulture` (hot, dry; carrion only, spots it 18 blocks away) and `Sparrow` (mild; flocks; tall grass and bushes, spreads seeds; foxes catch them). Clients draw them with the `Fly` gait (`AnimalViews.WriteFlyMatrices`): a move is a flight in an arc up to `flightHeight` at `walkSpeed`, the wings (rig motion `Wing`: plates hanging from a hinge on the body's sides) raised out and beating `wingbeatsPerSecond` times a second, and folded at rest (shortened to `wingFold`); `AnimalModelBuilder` gives flying birds such wings (`WingSpan`). Over 500 days on two seeds in a 512 world every species holds (from day 100: crows 26–129, vultures 30–75, sparrows 42–117; the others as before; about 33,000–35,000 plants, 2.9–3 ms per step). Sparrows first ate dry grass too and bred faster: over 1,000 of them starved the jerboas, hence their tighter territory (12 with up to 4 neighbours) and diet. `BirdTests` cover landing on anything, flying over a wall, a seed sown elsewhere and a carried seed kept across a save.
- **Carrion** (`Ecosystem.Carrion.cs`, `Carcass`): an animal dead of hunger or old age, or killed by a player (`RemoveAnimal`), leaves a whole carcass where it fell; a predator's catch leaves remains of half a carcass. A column holds at most one carcass (meat adds up), and carcasses stand in nobody's way. Each step a carcass rots (a whole one in 3 days) and what it loses goes into the soil of its fertility cell, which may then rise up to 0.6 above its capacity and comes back down four times slower than it regenerates (`RegenerateSoil`), so plants thrive where animals died. Scavengers (`AnimalSpecies.EatsCarrion`: fox, wolf, bear, jackal) take carcasses in their food search like prey, a quarter of a carcass per meal. Carcasses are saved (`ecosystem.dat` format 4) and sent with the animal list (same message, same range); clients draw them as their species lying on its side about its body's centre (`AnimalViews.AddCarcass`; the body is the largest part), facing a way picked from the column. Over 500 days on two seeds in a 512 world every species still holds (about 240–290 carcasses at any time; foxes 28–91, jackals 15–55, the rest as before; 2.3–2.6 ms per step). `CarrionTests` cover rotting, enrichment and its return, scavenging, remains and saving.
- The new animals' models are generated by `Assets/Editor/AnimalModelBuilder.cs` (menu **Eco > Rebuild animal models**): a quadruped laid out from a few proportions (legs, body, neck, head, snout, ears, tail) plus features (antlers, horns, ruff, hump, flank stripe, saddle, a hopper's haunches and long feet, tail tip), written as parts, rig and gait into each `AnimalSpeciesAsset`, with one material per colour (`Animal<Species>_<Fur|Light|Dark|Accent>`). The rabbit was modelled by hand and is not in its table. **The fox and the deer come from sculpted models** (`Assets/Models/<Species>/`), turned into parts by `Assets/Editor/ModelAnimalBuilder.cs` (menu **Eco > Rebuild animals from models**, one `Spec` per species). The **deer** (`Deer.fbx`, 120,000 triangles, with its colour texture `Deer_Diffuse.png`): measured and built at 1.45 blocks long, then scaled up by `Spec.Scale` to 1.9 blocks (about 1.3 at the back, 2.4 to the antler tips; asset `height` 2.41, `width` 1.0, `strideLength` 1.3), its head (turned 38° aside in the model) turned forward before simplifying (`DeerPose`, fading out down the neck), simplified to about 3,600 triangles, its four legs cut under the belly (y = 0.52, pivots worked out as the middle of each cut; ears and tail too small to move), and coloured from the texture: each simplified triangle takes the colours of the original triangles it covers (`ColourField`, found by position since the texture coordinates do not survive the simplification), gathered into 6 tones by k-means (`GatherTones`), each tone a material `AnimalDeer_Tone<n>` written by the build. The **fox**, `Assets/Models/Fox/Fox.fbx` (a static low-poly mesh, no rig, no texture): scaled to 1.3 blocks long, simplified from 120,000 to 2,400 triangles (edge collapses by quadric error, which keep the silhouette), cut along planes (`FoxCuts`: behind the rump, under the belly, above the skull, so each moving part meets the body on one flat cut through its pivot, a clean hinge) and sorted by boxes in the animal's space into body, four legs, two ears and tail with their pivots, each cut closed on both sides by a cap (`AddCaps`: the mesh is hollow, so the crack a swinging tail opens would otherwise show through the animal), so the `Trot` gait animates it like the boxes, and painted by region with the fox's three materials (white throat, chest, belly and tail tip; black socks, ear backs and nose; then `SmoothColours` gives a triangle the colour that at least two of its neighbours in the same part share, which removes stray triangles and ragged edges), plus open eyes over the model's closed slits (`BuildEyes`: a dark almond and a glint per eye, each point projected onto the simplified surface and lifted a few millimetres off it), as flat-shaded meshes `Fox_<Part>_<Colour>.asset` in `Assets/Species/Models`. Each part also has a `shadowMesh` (`<name>_Shadow.asset`, the same surface with smooth normals) that casts its shadow instead: with flat-shaded facets, the light's normal bias moves each facet along its own normal in the shadow pass and the light leaked between them, riddling the shadow with holes. A part may thus be any mesh, not only the cube (`AnimalViews` sizes a carcass's body from the mesh's bounds; a part with a `shadowMesh` is drawn without shadow, and its shadow mesh into shadows only). Another model needs its own regions in that file.
- Animals are synchronised differently from plants: twice a second at most, each player (the host included) receives the complete list of animals within `plantViewDistance` + 32 blocks, and only when it may have changed. Animal models are lists of boxes in their `AnimalSpeciesAsset` (`parts`: the built-in cube, a material with GPU instancing, offset and scale; no rotation), with a parallel `rig` naming each part's motion (body, ear, front leg, hind leg, tail) and pivot; a part's side comes from its pivot's x (negative is left). Gaits: `Hop` (the rabbit), `Trot` (the fox: legs in diagonal pairs, one cycle per `strideLength`, the tail sways, also when standing), `Fly` (birds, see Birds) and `Glide`. Clients play each move between lists (`AnimalViews`) at the species' own pace (hops of `hopLength` blocks lasting `hopDuration`, or a walk at `walkSpeed`), then the animal waits for its next move; a move is never longer than one simulation step at the current speed, so at high multipliers it is quickened. Spreading the move over the whole step instead made a rabbit take seconds per hop. **The displayed position can still lag the server by up to one simulation step**; the server's reach check for a kill (`EcosystemSync.RequestKill`) allows for that. `PlayerController` strikes whatever is nearest along its ray through `EcosystemSync.TryStrike` (animal, plant, else block).
- `ecosystem.dat` format 5 adds the seed each animal carries, format 4 carcasses, format 3 animals; formats 4 (no carried seeds), 3 (no carcasses) and 2 (plants only) still load, and animals then arrive by immigration.
- **Commands** (`Command` in `Voxel.Core` parses them, `CommandSync` runs them on the server, `CommandConsole` + `Assets/UI/Console.uxml` is the command line, opened with T, Enter sends, Escape closes, placed every frame just above the inventory text, which grows with the number of items (`InventoryHud.OccupiedHeight`, screen pixels converted to the panel's units); while it is open `CommandConsole.HoldsInput` silences the game's keys in `PlayerController`, `InventoryHud` and `MapScreen`): `/help`, `/players` (connected players by NGO client id, the host is #0), `/tp <x> <z>` (on top of the column, water included), `/tp <x> <y> <z>`, `/tp <player number>`, `/spawn <animal or plant> [count ≤ 20]` (where the player aims: adults via `Ecosystem.TryPlaceAnimal`, grown plants via `Ecosystem.TryPlaceGrownPlant`, which ignores climate, fertility and spacing). Every player may use them. A teleport is applied by the player's own machine (`PlayerController.Teleport`, through `NetworkTransform.Teleport`), the server only says where. A right click on the full-screen map sends `/tp` to the column under the pointer. `CommandTests`, `PlacementTests`.
- Simulation speed commands (F5/F6/F7, `EcosystemSync.RequestMultiplier` / `RequestAdvanceDays`) are only honoured for admins: the host of a hosted game, or players listed in the server's `-admin <id,id>` argument. `-timescale <x>` sets the starting speed.
- Plant materials must have **GPU instancing enabled in the asset** (`PlantRenderer` draws with `Graphics.RenderMeshInstanced`); enabling it only at runtime would let the build strip the shader variant.
- **A plant species has several models** (`SpeciesAsset.models`, each a list of parts). Each plant shows the one its column picks (`SpeciesAsset.ModelAt(x, z)`, a hash), turned by a quarter turn also picked from its column (`PlantRenderer`); display only, the same on every machine, nothing sent or saved, so models can be added or changed freely. `PlantRenderer` batches per look (species × model) then per part; the maps use each model's own colour and crown size. A species' `height` (aiming box) is that of its tallest model.
- The plants' models are generated by an editor script, `Assets/Editor/PlantModelBuilder.cs` (menu **Eco > Rebuild plant models**), which writes them into the species assets (`SpeciesModels`: two models per species, three bushes; a missing species asset is created): each made of boxes merged into one mesh per material in `Assets/Species/Models` (`<Model>_<Material>.asset`). It also writes the 64 × 64 grey textures (`Bark.png`, `Leaves.png`, one tile per block like the block atlas, with mipmaps) and the materials (`PlantTrunk`, `PlantBarkPale`, `PlantLeaves`, `PlantLeavesLight`, `PlantLeavesDry`, `PlantNeedles`, `PlantBush`, `PlantBerry`, `PlantGrass`, `PlantStraw`, `PlantCactus`, `PlantReed`, `PlantReedHead`: URP Lit, instancing on, the texture tinted by the base colour, which is also the maps' colour). Edit the tables there and rerun the menu: assets are rewritten in place, so references survive. Within a model, boxes must never have faces in the same plane, or they flicker.
- `PlantRenderer` groups plants into 32-block regions and only prepares and draws regions within `EcosystemSync.plantViewDistance` (128 blocks) of the main camera. Drawing every plant in the world each frame dropped a final-size world to 19 fps.

Inventory and specialities (rules in `Voxel.Core`, networking in `InventorySync`). **There is no crafting**: it was removed, with its recipes, the crafted blocks and the Carpenter and Mason specialities.

- An item is an `int` (`Items`): block types keep their number, other items use reserved ranges above (`Items.Wood`, one seed per plant species at `Items.Seed(speciesIndex)`). Like plants, **seeds reference their species by index**, so reordering species also breaks saved inventories.
- Each player has an `Inventory` (a count per item, no capacity limit) and one `Speciality`, both inside `PlayerState`, which `PlayerStore` saves in `players.dat` (format 2; format 1, positions only, still loads). `PlayerState` is a class and `PlayerRegistry` hands out the stored instance (`TryGetState`): mutate it in place, never replace it.
- **The server owns every inventory.** Breaking a block gives `Items.DropOf` (grass gives dirt), placing one consumes it (`WorldSync.TryApplyEdit` refuses a placement the player cannot pay for), felling gives wood by plant size (`SpeciesAsset.WoodYield`) and one seed if the plant was mature. Server code changes an inventory only through `InventorySync.TryConsume` / `Give`, which also send the new state to its owner; a client knows only its own inventory (whole state resent on each change, `Inv.State`), and the host reads the server's copy directly.
- A speciality is chosen once and never changed (`Specialities`). The only one offered is Gardener, the only one who can plant seeds (`InventorySync.RequestPlant`). `Speciality.Carpenter` / `Mason` keep their values so that old saves load: `PlayerStore` resets them to None, and those players choose again. Players hand items to the nearest player within reach (`RequestGive`).
- `InventoryHud` draws the inventory and reads its keys (wheel or 1-9: held item, K: speciality, G: give). `PlayerController` right-click uses `InventoryHud.SelectedItem`: a block is placed, a seed is planted in the targeted column.
- Block types (`Blocks`, 0–25): air, granite (`Stone`), dirt, grass, water, ice, five more rocks, sand, snow, gravel, clay, seven ores, bedrock. **Types 4–6 and 26–31 are retired** (the crafted blocks: planks, bricks, timber frame, cut rocks) and never reused: `Blocks.IsRetired`, they are not valid blocks or items, `ChunkSerializer.Read` turns them into air and `Inventory.Read` drops them, so old saves still load. `BlockAtlas` maps each type to one tile (`TypeTiles`; grass has a top and sides), 22 tiles of 64 × 64 pixels in one row, drawn by code. Soils and ice use pixel noise for grain (a ragged lower edge to the grass band). The rocks (`BlockAtlas.Rocks.cs`: granite, basalt, limestone, marble, sandstone, slate, gravel, bedrock, the ores, rock salt, flint) and snow (drifts and wind ripples, sparkles; bluish, never pure white, since a whiter snow saturates to a flat pink under the bright warm sun) are drawn like pixel art: each pixel's shade is picked from a palette of 3–5 shades per rock (`Ramp`, with 4 × 4 Bayer dithering between shades), from a tone that follows the rock's structure (Voronoi cells for crystals, columns, plates, pebbles and ore crystals gathered in veins; fBm smooth noise for beds and the turbulence of marble veins) and from a relief lit from the upper left (`RockHeight`). Every pattern wraps around the tile, so it runs on across blocks. To preview the tiles, call `CreateTexture` by reflection and blit it to a `RenderTexture` (the texture is not readable). Its mipmaps are made tile by tile (`BlockAtlas.HalveTiles`, down to 4 × 4 tiles) so that no colour bleeds between tiles: with point filtering, blocks stay sharp up close and do not shimmer far away. New block types need a tile in `BlockAtlas` (and a map colour in `BlockAtlas.MapColour`), a name in `Items.NameOf`, and `Blocks.LastType` updated (it bounds what the server accepts from clients and what a save may contain).

Scale (measured in the Editor at the planned final size, 64 × 8 × 64 chunks = 1024 × 128 × 1024 blocks, `-worldsize 64,8,64`): the host starts in about 4.5 s and uses about 1.5 GB; a dedicated server starts in under 1 s and uses about 600 MB; sending the whole world to a joining player is 2.6 MB in under 6 s, and that player is in game after about 8 s; a mature forest is about 85,000 plants. Those figures predate client-side generation: a joining player now receives only modified chunks. Still not done at that size: per-player chunk subscriptions (every client holds the whole world), skipping GameObjects for empty chunks, and off-thread meshing.

Networking (Netcode for GameObjects 2.x, Unity Transport, direct IP; the UDP port is set on `GameSession` in the scene, currently 50000):

- `GameSession` owns starting and stopping, in three roles: host (`-host`, or the main menu), client (`-connect <address>`, or the main menu), and dedicated server (`-server`, implied by `-batchmode`). F10 leaves. Screens drive it only through its public API (`Host`, `Join`, `Leave`, `Quit`, and the state `InMenu` / `IsConnecting` / `IsLoading` / `LoadingProgress` / `Message`, the last problem to show). Other arguments: `-port`, `-password`, `-data <dir>` (server save folder, default `Application.persistentDataPath`), `-autosave <seconds>`, `-playerid <id>`, `-worldsize <x,y,z>` (server world size in chunks, overriding the scene), `-noupnp`.
- **Dedicated server**: the Dedicated Server build module is not installed, so the server is the normal player run headless. `VoxelWorld` skips all meshing and rendering when `Application.isBatchMode` is true, the frame rate is capped to the network tick rate, and the process quits if the server stops.

```powershell
& "A:\dev\ECO 2\Builds\Test\ECO2.exe" -batchmode -nographics -server -password secret -data "D:\eco-server" -logFile "D:\eco-server\server.log"
```

- **Router port forwarding (UPnP)**: when a server or host starts, `GameSession` asks the home router to forward the UDP port to this machine (`PortForwarding` / `UpnpGateway` / `UpnpProtocol` in `Voxel.Core`, written by hand: no library), renews it every hour and removes it when the session ends. It is best effort: the result is one log line starting with `Internet:` (also shown on the host's screen), and a refusal never stops the server. All router calls block, so they only run on background tasks; on quit the removal is waited for (up to 4 s). Disable with `-noupnp` or the `openRouterPort` checkbox. **Pass `-noupnp` to servers launched for testing**, so tests never change the user's router. The tests use a fake router on localhost. Everything a router sends is treated as untrusted (description and control URL must be on the device that answered, DTDs refused, answers capped in size). UPnP cannot help when the router has no public address (the summary says so) and does not open the Windows firewall.
- **Server role teardown differs from client teardown**: a dedicated server never raises `OnClientStopped`, so `GameSession` ends a session on both `OnServerStopped` and `OnClientStopped` (a host gets both; `sessionActive` makes it idempotent).
- `PlayerRegistry` (server only, plain class created by `GameSession`) is the connection approval callback. It checks the password (empty = open server), refuses a player id that is already connected, and spawns the player at the position saved in `players.dat`, raised out of any block built there since. A client's id comes from `PlayerIdentity` (a GUID file in `persistentDataPath`; **the Editor uses a separate file from builds** so both can join the same server from one machine). The id and password travel in the NGO connection payload (`ConnectionRequest`), unencrypted.
- **Saving happens on the server only** (`world.dat`, `players.dat`, `ecosystem.dat` in the data folder): every `autosaveInterval` (60 s), when a player disconnects (players only), on F10 and on quit. **A player's object is already unreadable when NGO reports the disconnection or the end of the session**, so `PlayerRegistry.TrackPlayers` records every connected player's position each frame. `GameSession.EndSession` saves everything once more before tearing the session down, because on quit the network can stop before `OnApplicationQuit` reaches `GameSession`. A killed server loses at most one autosave interval.
- The client shows the server's refusal reason only when it is one of the texts in `ConnectionRefusal` (`Voxel.Core`); any other `NetworkManager.DisconnectReason` is NGO's internal wording and is replaced by a generic message.
- The server's world is persistent (loaded from and saved to `world.dat`). **A client never reads or writes a world file**: it generates the terrain itself from the server's seed, and `WorldSync` then receives only the chunks modified since generation.
- `WorldSync` uses NGO named messages, not RPCs or `NetworkVariable`s, so it needs no `NetworkObject`: on connection, world info (size, seed, generator version, `World.TerrainFingerprint`, number of modified chunks), then the modified chunks (`ChunkBatch`, one batch of at most 16 KB per client per network tick, nearest first), then one message per block change. The client generates the world inside the world-info handler, so later messages always apply on top of generated terrain. If its generator version or terrain fingerprint differs from the server's, it leaves with `WorldSync.Failure` set (shown in the menu) rather than play on mismatched terrain. Chunks are serialized when sent, and all these messages share one reliable ordered channel, so a block changed during the transfer is never lost. Every client currently receives the whole world and every change; per-player chunk subscriptions are left for the load test.
- `PlayerRules` (`Voxel.Core`) holds the player size, eye height and reach used by both the local simulation and the server checks.
- The server chooses each player's spawn position in `GameSession.ApproveConnection` (connection approval is enabled for that reason). Scene management is disabled in the `NetworkManager`: there is a single scene and a reload would destroy the loaded world.
- `Assets/Prefabs/Player.prefab` is the player prefab. Its `NetworkTransform` is **owner-authoritative**; `PlayerController` is a `NetworkBehaviour` that stays disabled except on the owner, which simulates movement locally. The scene's Main Camera is not parented to the player; the owner repositions it every frame.
- The player's body is built at runtime by `PlayerModel`: eleven joint pivots (hips, spine, head, shoulders, elbows, thighs, knees), each carrying one mesh of boxes (head with hair, nose and ears; chest with straps and backpack; shin with shoe; forearm with hand), textured by `PlayerSkin`, a runtime texture of 32-pixel tiles like the block atlas; `Assets/Materials/Player.mat` only supplies the shader settings. On side faces the tiles run from back to front on both sides. Its animation (walk with knee and elbow bends, jump, idle breathing) is procedural and **derived from how the player object moves**, so remote copies animate from the `NetworkTransform`. The one extra value on the network is the gaze pitch: `PlayerController.Look` calls `PlayerModel.SetLookPitch`, which writes an owner-writable `NetworkVariable<sbyte>` in whole degrees only when it changes; the head follows it up to 70° and the chest does not. **The owner's camera sits at the eyes of that head** (`PlayerModel.EyeOffset(pitch)`, used by `PlayerController.PlaceCamera`): the head turns about the neck, so looking down moves the camera about 0.21 forward and 0.2 down, in front of the chest and still inside the collision box. That is what lets the owner see its own body; only the owner's head joint (which also carries the neck) is hidden, as a shadow caster. `PlayerRules.EyeHeight` is still what the server uses for reach checks. The shirt colour comes from the NGO client id, so it can change from one session to the next.
- **Appearance** (`Appearance` in `Voxel.Core`: sex, skin tone, eye colour, hair style, hair colour, facial hair, one 16-bit code where 0 means "not chosen"; **all 16 bits are now used**, so another choice needs a wider code, a new `players.dat` format and a wider `NetworkVariable`; colour index 0 is the colour everyone had before colours were added, so codes saved without them keep their look; the colours themselves are in `PlayerSkin`, their names in `Appearance`) is chosen once, at a player's first connection, in `AppearanceMenu`, and kept in `PlayerState` (`players.dat` format 3; older formats load with no appearance, so those players get the menu once). The server writes it into an owner-independent `NetworkVariable<ushort>` on `PlayerModel`, set in `OnNetworkSpawn` from `AppearanceSync.StoredCode` so clients never see the default first (the host's own player spawns before `AppearanceSync.StartServer`, which then publishes it). A choice is sent with the `Look.Choose` named message and refused once one exists. `PlayerModel` rebuilds its meshes and texture whenever the appearance changes (`Preview` does it locally while choosing). While the menu is open, `PlayerController` freezes the player and puts the camera in front of it, and the head is shown. Dragging beside the panel turns the body with `PlayerModel.SetPreviewYaw`, which rotates only the local model (not the player object, so nothing is sent); it is reset when the menu closes.
- **UI is moving from IMGUI to UI Toolkit**, one screen at a time. Done: the main menu (`MainMenu` + `Assets/UI/MainMenu.uxml`: home, host, join, then connecting/loading progress and the last error; Options is a disabled placeholder), the minimap and the full-screen map (below), character creation (`AppearanceMenu` + `Assets/UI/CharacterCreation.uxml`) and the **aiming label** (`TargetLabel` + `Assets/UI/Target.uxml`, object `TargetUI` in the scene: a pill under the crosshair naming what the player aims at within `PlayerRules.Reach`, the animal or plant a click would strike, from `EcosystemSync.TryAim`, else the block's `Items.NameOf`; a plant not yet grown is "Young oak"; names come from the asset names, "TallGrass" shown as "Tall grass"; hidden in the menu, with character creation or the full-screen map open, and when nothing is in reach). Aiming at plants, for the label and for strikes, only looks at the columns the ray crosses (`EcosystemSync.plantAtColumn`, kept with the plant views; a plant's aiming box stays within its column), so it costs nothing however many plants there are. New screens use a `UIDocument` with `Assets/UI/PanelSettings.asset` (scaled from 1920 × 1080, theme `Assets/UI/Theme.tss`) and the shared style sheet `Assets/UI/Common.uss` (a light theme: cream panels, dark text, green primary buttons; colour variables, the Inter font, icons, buttons, keycaps, dialogs, `.hidden`). The font (`Assets/UI/Fonts`, Inter, SIL OFL) and the icons (`Assets/UI/Icons`, Phosphor, MIT; white PNGs tinted with `-unity-background-image-tint-color`) were copied from the App UI package with their licence files; keep those files next to them. Editing a UXML or USS file during Play mode makes the Editor rebuild the document, which loses what the screen's code added to it (values, colour swatches): restart Play mode to see the real result; the scene's `EventSystem` with `InputSystemUIInputModule` gives them the mouse. The C# side only queries elements by name, fills them in and registers callbacks: the look stays in UXML/USS. Keyboard shortcuts are read from `Keyboard.current` by the screen itself, and its buttons are made non-focusable so that UI navigation does not compete with them. Text fields (`TextField`) do take typing: UI Toolkit reads it from the OS keyboard events, not from the Input System, so text queued with `InputSystem.QueueTextEvent` never reaches them (to test, send a `KeyDownEvent` to the field). While the character creation screen or the full-screen map is open, the IMGUI texts of `GameSession` and `InventoryHud` are hidden.
- **Maps**: both draw one picture of the whole world, `WorldMap.Texture` (one pixel per block column, display only, nothing on the network). `WorldMap` reads the terrain from this machine's world (`WorldSync.World`) in tiles of 16 × 16 columns, nearest to the player first, within 1.5 ms per frame (a 512 × 512 world is read in a few frames), keeps it, and rereads a column on `World.BlockChanged`; plants come from `EcosystemSync.PlantShown` / `PlantHidden` / `PlantsCleared`. A tile is redrawn into the texture only when something in it changed (crowns overlapping from neighbouring tiles included), and the texture is uploaded at most ten times a second, so the maps cost nothing while nothing changes: they only move and scale the picture. Each column's top is read with water counted (`World.GetTopHeight`); water is drawn flat and darker the deeper it is (`BlockAtlas.WaterColour`). Colours come from the assets: blocks from `BlockAtlas.MapColour`, a plant (per model) or animal from the material of the part with the most upward-facing area, a crown's size from its meshes' bounds, so a new species needs no setting. Animals (`EcosystemSync.GetAnimalPositions`, only those near the player are known), other players (NGO's spawned player objects) and the player's arrow (`MapArrow`, drawn with `Painter2D`, colours from the USS properties `--arrow-fill` / `--arrow-outline`) are elements placed every frame by `MapMarkers`; their styles are in `Assets/UI/MapMarkers.uss`.
  - The **minimap** (`Minimap` + `Assets/UI/Minimap.uxml`) is a round window at the top right, north up, 64 blocks from centre to rim, with the player's coordinates below.
  - The **full-screen map** (`MapScreen` + `Assets/UI/Map.uxml`) opens and closes with M (Escape also closes it); it is looked up with `FindKeyOnCurrentKeyboardLayout("m")`, since on AZERTY M is the key QWERTY calls semicolon. While it is open the mouse is free (wheel: zoom around the pointer, from the whole world to 12 pixels per block; drag: move; Space: follow the player again; Tab: climate layer, terrain → temperature → humidity, drawn from `Geography` over the picture), the coordinates, temperature and humidity under the pointer are shown, the minimap and the IMGUI texts are hidden, and `PlayerController` keeps the player still (`MapScreen.HoldsInput`, also true on the frame the map closes so that its key does nothing else). Closing it captures the mouse again.
- The remaining on-screen text (in-game session info, inventory) is still drawn with `OnGUI` for display only; its input is read from `Keyboard.current`.
- The block texture atlas is generated at runtime by `BlockAtlas`; `Assets/Materials/Blocks.mat` only supplies the shader settings. Its shader is **`ECO/Blocks`** (`Assets/Shaders/Blocks.shader`): URP's Lit shader copied from the installed package with only its name and forward pass changed (`BlocksForwardPass.hlsl`, the parts marked "ECO"), so shadows, Forward+ (PC), Forward (Mobile) and SSAO behave as before; after a URP upgrade, copy `Lit.shader` / `LitForwardPass.hlsl` again and reapply them. The atlas's **alpha channel is the tint mask**, not transparency (grass top and the green band of its sides are 0, drawn light grey): those pixels are multiplied by the climate's grass colour, read from the global texture `_ClimateTint` (one pixel per geography cell, blended) that `ClimateTint` builds from `Geography` when a world appears (a mild colour before). `ClimateColours` holds the colours (grass, map layers, °C and % readings) shared with the maps, whose grass follows the climate too. The deferred (GBuffer) pass is URP's own and does not tint; neither pipeline uses deferred.
- **Sky light** (`SkyLight`, `Voxel.Core`, display only: worked out by each machine that draws the world, never on a batch-mode server, nothing sent or saved): every cell gets 0 to 15. Air with only air above it up to the top of the world is 15, so a shaft gets open sky all the way down; every other step (sideways, upwards, into or through water) loses one level; opaque blocks hold 0. Levels are kept per chunk, as a single value for a uniform chunk (open sky, deep rock). `VoxelWorld` builds it when a world is shown (about 150 ms for 512 × 512, 700 ms for 1024 × 1024), updates it from `World.BlockChanged` (`SkyLight.Update`, a few microseconds: light is taken away from what the change darkened, then flows back) and from chunks replaced wholesale (`UpdateChunk`, for the modified chunks a client receives), and remeshes the chunks whose levels changed. `SkyLightTests` check that updates always give what computing the world again gives. `ChunkMesher` writes it smooth into each vertex's colour (red: the mean of the four cells in front of the face around that corner, opaque ones left out; quads split along their brightest diagonal), and `ECO/Blocks` multiplies everything a face receives (sun, ambient) by a curve of it, down to `VoxelWorld.darkestSkyLight` (global `_DarkestSkyLight`, 0.02: underground is really dark). Things drawn with other shaders do not read it, except the players' bodies (`PlayerModel` shades its material with `VoxelWorld.SkyBrightnessAt`, the same curve); plants and animals stand under the sky anyway. Water uses the same shader (transparent), lit by the air in front of each face: dark in a cave. There are no torches yet (no block light): they wait for a way to make them now that crafting is gone.
- **Day and night** (`DayNight`, on its own object in the scene): the hour comes from the simulation's clock (`EcosystemSync.StepTime`, the last known step count carried on at the current speed, so every machine sees the same hour without a message of its own; `SimClock.MinutesAt`, a simulation starts on day 1 at 8:00). One game day is 144 steps, 24 real minutes at speed 1, and passes as fast as the simulation when an admin speeds it up. The scene's directional light is the sun from 6:00 to 20:00 (east, south at midday up to 60°, west, warmer near the horizon), then a faint bluish moon opposite; the sky's ambient probe, the reflections and the skybox's exposure (on a copy of the skybox material) fade with `DayNight.Daylight`, and the underwater fog too. Nights are dark on purpose. In the menu the scene's lighting is given back exactly. Nothing in the simulation depends on the hour.

## Working with the Unity Editor

The Editor is driven through the **MCP for Unity** package (`com.coplaydev.unity-mcp`, tools named `mcp__unityMCP__*`). It only works while the Editor has this project open and the MCP bridge is running; load the `unity-mcp-skill` skill before using it.

- After creating or editing a script, Unity recompiles and reloads the domain. Tool calls made during that window fail or return stale results, so confirm compilation finished and check `read_console` for errors before using the new type.
- `manage_components(action="add")` has failed to resolve a freshly compiled project script by name even after compilation succeeded. Fallback: `execute_code` with `Undo.AddComponent(go, type)`.
- Scene edits made through MCP are not persisted until `manage_scene(action="save")`.
- World sizes (`VoxelWorld.sizeInChunks`, `GameSession.worldSize`, `-worldsize`) are in **chunks**, not blocks. The scene's default is 32 × 8 × 32 chunks (512 × 128 × 512 blocks): a host starts in about 1.8 s in the Editor. Passing a block count (128 per axis is two million chunks) freezes the Editor until it is killed.

## Conventions that are easy to get wrong

- **Language**: everything in the project is English — comments, log and exception messages, inspector headers and tooltips, the text shown to players, and asset names (the plant species are `Oak`, `Bush`, `Birch`, `Pine`, `Acacia`, `Poplar`, `TallGrass`, `DryGrass`, `Cactus`, `Reeds`, the animals `Rabbit`, `Fox`, `Deer`, `Reindeer`, `Wolf`, `Bear`, `Gazelle`, `Jackal`, `SnowHare`, `Jerboa`, `Fish`, `Duck`, `Heron`, `Otter`, `Crow`, `Vulture`, `Sparrow`; a seed is displayed with its asset name). Renaming a species makes existing `ecosystem.dat` files fail to load (the save records species names).

- **Input**: active input handling is the new Input System only (`activeInputHandler: 1`). `UnityEngine.Input` (`Input.GetKey`, `Input.GetAxis`) throws at runtime; use `UnityEngine.InputSystem`.
- **Keyboard layout**: the target layout is AZERTY (ZQSD movement). Input System `Key` values are physical positions named after the QWERTY layout, so `Keyboard.current.wKey/aKey/sKey/dKey` is ZQSD on AZERTY. Do not use `zKey`/`qKey` for movement.
- `Assets/InputSystem_Actions.inputactions` is registered as the project-wide actions asset, but `PlayerController` currently polls `Keyboard.current` / `Mouse.current` directly and does not use it.
- **Rendering**: URP with two quality levels, `Mobile` and `PC`, each bound to its own pipeline asset and renderer in `Assets/Settings/` (PC: Forward+ with SSAO; Mobile: Forward). Rendering changes usually need to be applied to both. With the Standalone build target the Editor only offers `PC`; `Mobile` is for mobile platforms. **Both have a shadow normal bias of 0** (PC depth bias 0.1): a normal bias shrinks every face of the casters, which opened slits where blocks meet along an edge, and at a low sun the light through them drew long bright lines on the ground and lake beds; checked at 9:00, 13:00, 17:00 and sunset without shadow acne. Two-sided shadow casting did not help.
- **Assets**: every asset needs its `.meta` file committed alongside it; move or rename assets through Unity (or move the `.meta` with them) so GUID references survive. Binary assets are tracked with Git LFS and Unity YAML uses the `unityyamlmerge` driver (see `.gitattributes`).
