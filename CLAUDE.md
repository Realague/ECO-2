# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Unity **6000.6.5f1** project (URP 3D template): a multiplayer block-world game in the spirit of *Eco*: the server simulates an ecosystem (plants that grow, spread and die) that players affect. Current state: voxel world, dedicated-server multiplayer, and a first plant simulation. One scene (`Assets/Scenes/SampleScene.unity`, the only scene in the build settings). `Assets/TutorialInfo/` and `Assets/Readme.asset` are leftovers from the Unity template, not project code.

## Architecture

Code is split into assemblies so that a future dedicated server can run the world without rendering:

- `Assets/Scripts/Voxel.Core` — blocks, chunks, world, generation, collision, raycast. **Pure C#: the asmdef sets `noEngineReferences`, so `UnityEngine` is unavailable here.** Vectors are `System.Numerics.Vector3`; positions are `BlockPos` / `ChunkCoord`.
- `Assets/Scripts/Eco.Sim` — the ecosystem simulation: the soil (NPK), plants, species rules, simulation clock, save format. **Pure C# as well (`noEngineReferences`), depends only on `Voxel.Core`.**
- `Assets/Scripts/Voxel.Client` — meshing, rendering, input, player, and for now the session/network code. Converts vectors at the boundary with `ToNumerics()` / `ToUnity()`.
- `Assets/Tests/Voxel.Core.Tests`, `Assets/Tests/Eco.Sim.Tests` — EditMode tests for the two pure assemblies.

Key rules:

- `World.SetBlock` is the only way gameplay code changes a block. It marks the chunk modified and raises `World.BlockChanged`, which remeshing listens to (networking and saving will hook in the same way). `Chunk.Set` is a raw write for generators only.
- `World.IsSolid` treats everything outside the world's sides and bottom as solid (keeps players in, culls unseen faces); `World.GetBlock` returns air there. **Solid, opaque and replaceable are separate** (`Blocks`): water is none of solid (players and rays pass through it, it cannot be broken), opaque (faces next to it are drawn, so a lake's bed shows; use `World.IsOpaque` for face culling) or occupied (a placed block pushes it out, `Blocks.IsReplaceable`). Use `IsSolid` for collision, support and aiming. `World.GetSurfaceHeight` is the top of the solid ground (under water, the bed); `World.GetTopHeight` counts water (what is seen from above). A player never sets water (`BlockEditRules`).
- A block is a `ushort`: low 8 bits are the type (types stay below 100, where the item ranges begin), the next 4 a variant (`Blocks.VariantOf`, only wood blocks' shapes use it; those bits were part of the type before, and no type ever reached them, so saves read the same), high 4 bits the orientation. Compare types through `Blocks.TypeOf(block)`, never the raw value.
- `WorldSave` stores a header (seed, generator version, dimensions) plus **only the modified chunks**; untouched chunks are regenerated on load. Any change to what a generator produces must bump `IChunkGenerator.Version`, which makes older saves fail to load instead of loading corrupted. `ChunkSerializer` (run-length encoded) is meant to be reused as the network chunk format.
- A persistent world is loaded from `world.dat` in its folder and written back by `VoxelWorld.Save` and `Unload`. **A saved world keeps its own seed and size** (read from the save); only a new world takes the seed it is given (`VoxelWorld.LoadPersistent(directory, size, newSeed)`, else the scene's `seed` and `sizeInChunks`), and it is saved at once. A save that fails to load (another generator version, a damaged file) is replaced by a new world with a warning. **Each hosted world has its own folder** (`WorldSlots`, `Voxel.Core`): `Saves/<name>/` in the data folder (`world.dat`, `players.dat`, `ecosystem.dat`), plus the data folder itself when it holds a world (listed as "World": games hosted before the list, and the `-host` and `-server` options, still save there). `WorldSlots.List` reads each save's header only (`WorldSave.ReadHeaderFromFile`: seed, generator version, size), the most recently played first; `CreateDirectory` turns a typed name into a folder name every system accepts (`FolderNameOf`) and numbers it if taken; `SeedOf` reads a typed seed (a whole number, or a word hashed with FNV-1a, the same on every machine; empty gives a random one). `WorldSlotsTests`.
- Terrain comes from `TerrainGenerator` (version 6: plains, hills, bare-rock massifs from `ReliefHeight`, relief below 64 blocks, plus water, marshes, rocks and caves). **Server and clients each generate the same world from the seed, so generation must be bit-identical on every machine**: it uses only integer math (`IntNoise`, fixed point with `IntNoise.One` = 1; `IntNoise.TurnedFractal` blends a grid turned by about 53° so that value noise leaves no straight valleys), never floats, `System.Random` or anything order-dependent. `TerrainGeneratorTests` pins reference heights and a world fingerprint; if they change, the generator's output changed and `TerrainGenerator.Version` must be bumped (old saves are then refused, and clients on another version are turned away). `IChunkGenerator.Prepare(seed, sizeX, sizeZ)` is called by `World.Generate` before any chunk: what depends on the whole world is worked out there.
- **Water** comes from `Landscape` (`Voxel.Core`, `Landscape.For(seed, sizeX, sizeZ)`, the last one cached): the relief lowered into lake basins and, along the west edge, under a sea (`SeaLevel` = 20, the plains' height, so shores are flush); a **priority flood** from the world's edges held at sea level fills each hollow to its rim (lakes; those under 150 columns are filled in as land instead); a second flood over the final relief, with smooth noise of up to 2.5 blocks so that water wanders on flat land, gives each column the neighbour it drains to, and **rivers** are carved where the catchment exceeds 3,000 columns (3 wide above 15,000, 2 deep above 40,000), flush with the lowest ground around so water never stands above its banks (`LandscapeTests.Water_IsHeldByItsBanks`). Ice tops water where the climate is cold. About 17 % of the land is water.
- **Marshes** (`Landscape.LayMarshes`, version 6, worked out after `Geography`, so the climate is that of the land before them; `Landscape.IsMarsh` / `IsMarshPool`): dry, gentle land (neighbours within 1 block), at most 4 blocks above sea level, not bare rock, with temperature ≥ 0.25 and humidity ≥ 0.66 (the threshold moved up to a tenth either way by noise of about 32 blocks, for ragged edges); stretches under 300 columns are dropped. In them, where noise of about 4 blocks is high, a **pool** one block deep is dug if none of its 8 neighbours is lower or holds water: its water stands where its ground was, so it is always held, and two pools side by side are at the same height. Pool beds are `Blocks.Mud`, the land between them grass on mud. In a 512 world: 3.6 % (seed 1), 2.7 % (seed 2), 10 % (seed 3) of the world, about a third of it pools (`LandscapeTests`, which also pins a fingerprint of the whole 512 landscape, since the small world of `TerrainGeneratorTests` holds no marsh). The landscape now takes about 0.45 s for 512 × 512.
- **Geology** (`Landscape.LayGeology`, `Landscape.Column`, `TerrainGenerator.RockAt` / `OreAt`, version 4): from the bottom, bedrock (y = 0, ragged on y = 1–2, unbreakable: `Blocks.IsBreakable`), the granite basement (`Blocks.Stone` is granite), then a cover rock 8–24 blocks thick chosen by region: limestone where it is mild, sandstone where it is dry and warm, slate where it is cold, basalt in volcanic provinces (about one in ten, zones of 256 blocks). Above height 40 the cover thins by 3 blocks per block, so the massifs' heights show granite. Marble is a 2-block band at the base of thin limestone (≤ 12) on ground ≥ 30. The top block and the 3 under it: grass on dirt; snow on dirt where it is coldest or high and cool (also on bare rock); sand on sand in dry warm regions and on beaches within 2 of a lake or the sea; under water gravel (rivers), clay (lakes), sand (sea) or mud (marsh pools); marsh land is grass on mud. Ores are decided per block from an integer hash: cells of 4 × 4 × 4 hold ore with a chance by host rock and depth (sedimentary: coal, flint in limestone near the surface, rock salt in sandstone; granite: copper, tin only in cold regions, gold below 25 blocks; basalt: iron; iron a little everywhere), then 3 blocks in 4 of the cell are ore. In a 512 world that is about 8 ‰ coal, 7 ‰ iron, 4 ‰ copper of the solid blocks, gold under 1 ‰ (`GeologyTests`). Before plant species had climates, deserts and snow were bare: with them the food chain was re-checked over 450 days on two seeds in a 512 world (rabbits 476–883, foxes 92–151). It takes about 0.6 s for a 1024 × 1024 world, on the server and on each client. **Water does not flow**, except that the server fills holes (`WaterFill`, called by `WorldSync.TryApplyEdit` when a block is broken): a block that becomes empty with water beside or above it takes water, and so does the empty space joined to it sideways or below, never above; a space over 4,096 blocks is open land and is left dry. The server sets those blocks 64 per frame.
- **Caves** (`Caves`, `Voxel.Core`, built by `Landscape` with the rest, carved by `TerrainGenerator.Generate` into each chunk with `Caves.Carve`, version 5): hollows (rounded volumes: a tunnel's section, a cavern's wide low dome with a flatter floor) strung along tunnels that wander like worms, one block per step, turning and tilting a little each step (angles in whole degrees, sines from Bhaskara's integer formula, positions in 1/16 block, an xorshift seeded per region: no floating point). Each region of 32 × 32 columns may hold a system (70 % in limestone, the karst, 45 % in basalt, 35 % elsewhere): 30 % open on the surface (entrances, on dry land only), tunnels fork, some widen into caverns (more in limestone), caverns keep 4 blocks of rock over them, and in basalt half the systems are lava tubes (round, flat-floored, a few blocks under the ground, as long as they stay in basalt). Nothing is carved at y ≤ 2 nor within 4 blocks under surface water or within 2 columns of it, so lakes, rivers and the sea never stand over a void. Some caverns hold a **cave lake**: water up to a block or two above their floor in every hollow block joined to them below that level, found in a box around the cavern; a lake that would reach the open air, the box's sides or 4,000 blocks is not made, so cave water is always held by rock (`CavesTests`). In a 512 world: about 20,000 hollows, 70–85 caverns, 35–40 entrances, 15–20 lakes, 2.4 % of the underground volume; about 20 ms (50 ms for 1024 × 1024). Caves are dark (sky light), and plants and animals keep to the surface: no plant grows on bare rock, animals never drop more than 3 blocks.
- Water is drawn as a second submesh of each chunk (`ChunkMesher.WaterSubmesh`) with `Assets/Materials/Water.mat` (the blocks' shader `ECO/Blocks` in transparent mode, so it darkens with the sky light like the blocks; no shadow casting, no depth), its surface a little below the top of the block under air (`ChunkMesher.WaterSurface`, 0.875). The player swims (`PlayerController`): with the block at 0.4 above the feet in water, gravity is 30 %, sinking at most 2 blocks/s, Space swims up at 3, moving at 60 %; swimming against a bank (`MoveResult.HitWall`) with Space and a direction held gives the push of a jump, since swimming up alone never lifts the feet a block above the surface, the height of a flush bank; with the eyes under water, the scene's fog turns blue and short (given back when the eyes come out or the controller stops). Land animals never enter water nor walk on a bed (`AnimalMoves.GroundOf`); water animals have their own habitats (below); a plant needs air, not water, at its base, except water plants (below).
- **Climate**: `Geography` (`Voxel.Core`, `World.Geography`, worked out once from the seed and size) holds temperature and humidity on a grid of 8 × 8-column cells, in fixed point, under the same bit-identical rules as the terrain, so nothing is sent. Temperature: hot in the south (z = 0), cold in the north, zones of about 256 blocks, colder with altitude. Humidity: its own zones, multiplied by the air's moisture as a west wind carries it row by row: rising ground makes it rain (wet windward slopes), the land past a massif is dry (rain shadow), and rows are blurred together; land near water is wetter. `TemperatureAt` / `HumidityAt` blend between cell centres. `Geography.Create(seed, size)` is the one `Landscape` computes over its ground and water (as generated, never the edited world); tests build it over any relief with the other overload. `GeographyTests` pins reference values; changing the climate changes fertility and grass colour on every machine. It takes about 10 ms for a 1024 × 1024 world. World roadmap: 1 climate, 2 water, 3 geology, 4 sky light with day and night, 5 caves, 6 plant species, 7 land animals per climate, 8 carrion, 9 water animals and 10 birds are done (the world roadmap is complete). Steps 2, 3 and 5 changed generation (each bumped `TerrainGenerator.Version` and reset worlds); light did not. Marshes (with jungles, which only come from plant and animal species) bumped it again, to 6.
- The player uses voxel collision (`VoxelCollision.Move`), not Unity physics; chunks have no `MeshCollider`. Shaped wood blocks collide by their boxes and the player steps up half a block (see Building). Placed storage is solid too: `Move` takes an optional `extraSolid` predicate (`StorageSync.IsSolid`), so the player stops against a chest or a pile and can stand on it; **tree trunks** too: `Move` also takes `ICollisionObstacles` (boxes thinner than a block, gathered by column; `EcosystemSync` gives the trunk of every plant that gives wood at its stage, as wide as its stump's cut, `PlantRenderer.TryGetTrunk`, or a sixth of its width without a stump, and as high as its aiming box; a stump up to its cut, which can be stood on; saplings too small to give wood, bushes, grass and crops are passed through, and so are crowns): a box the player enters stops it at its face, one it was already in (a tree grown where it stood) lets it out (`VoxelCollisionTests`) (only the owner's machine simulates the player, so this is client-side like every collision). `transform.position` of the player is the centre of its feet.
- `VoxelWorld.World` only exists during a session; it is `null` in the menu. The host gets it from `VoxelWorld.LoadPersistent` (called by `GameSession` right before starting the network); a client gets an empty world from `VoxelWorld.CreateRemote` when the server's world info arrives. `GameSession` unloads it when the session stops.
- **Gameplay code reads the world through `WorldSync.World`**, which stays `null` until the world is fully available on this machine (on a client, until every chunk has arrived). The local player does not simulate before that.
- **Players never call `World.SetBlock` directly: they place blocks with `WorldSync.RequestSetBlock` (placing only) and break them by hits (`MiningSync`, whose last hit calls `WorldSync.TryBreak`).** The server validates every request (`BlockEditRules` in `Voxel.Core`, plus "not inside a player") and broadcasts accepted changes; a client applies its own request immediately and the server sends back the real block if it refuses.

Ecosystem simulation (`Eco.Sim`, run by the server only):

- **`Ecosystem.Step()` is the only thing that advances the simulation, and it must stay deterministic**: no real time, no `UnityEngine`, no `System.Random` (use the ecosystem's `SimRandom`, whose state is saved), and plants are processed in list order. Tests rely on "same seed + same calls = same forest", including across a save and reload.
- Time acceleration never changes what a step does: `SimClock` only decides *how many* steps to run (one step = 10 game minutes; at speed 1 that is 10 real seconds). Do not scale step effects by a delta time, and never use `Time.timeScale`. `EcosystemSync.Update` runs the due steps within an 8 ms budget per frame; steps queued by "advance N days" always run, backlog caused by the multiplier is dropped.
- **The soil is NPK** (`Ecosystem.Soil.cs`), on a coarse grid (`Ecosystem.CellSize` = 4×4 block columns per cell): each cell holds nitrogen, phosphorus and potassium (`SoilSample`, `Ecosystem.GetSoil` / `GetSoilCapacity`), each regenerating toward its own capacity at its own pace (per step: N 0.005 times the cell's pace, 0.5–1.5 from `ClimateRichness`; K 0.004; P 0.0035, the rock weathers slowly) and, above its capacity, coming back down four times slower. **Capacities come from the land**, read from the world at construction (4 columns per cell, not saved; about 110 ms for 512 × 512): phosphorus and potassium from the first rock within 12 blocks under the surface (limestone and marble rich in P, basalt in both, granite in K, sandstone poor, slate between), nitrogen from the climate (`Ecosystem.ClimateRichness`: wetness most, then mildness); then the top block changes them (sand and gravel poor in everything, snow poor, clay rich in K, marsh mud rich in N and K, bare rock little N) and cold lowers P and K; each is mapped to 0.4–1. Land capacities on seed 1 (512 world): N spread over 0.4–0.9, P in three peaks by rock (0.5–0.6, 0.7–0.8 and 0.9–1, a third of the land), K 0.7–0.8 on 60 % of the land. **A species' needs** (`Species.NeedNitrogen` / `NeedPhosphorus` / `NeedPotassium`, 0 to 1, `SpeciesAsset` "Soil (NPK)") weight the law of the minimum: what it finds to live on (`Ecosystem.Available`) is the lowest of 1 − need × (1 − level) over the nutrients it needs, and that replaced the old single fertility everywhere: below `MinSoil` (`SpeciesAsset.minSoil`, called `minFertility` before NPK) seeds do not take and plants starve, growth and ripening go at that times vigour. A plant draws `SoilUse × growth × need` of each nutrient every step (so a crop wears out its own nutrient, the point of rotating crops); legumes (`Species.FixesNitrogen`, `nitrogenFixPerDay`: beans and acacias, 0.3 a day) give nitrogen back, up to 0.6 above capacity; a plant dying where it stands (of age, of hunger, grazed to death) gives back two days of what it draws (`LitterDays`), one felled or harvested nothing; a carcass's meat goes 60 % to nitrogen, 40 % to phosphorus. Profiles (N / P / K): grasses and cereals 1 / 0.4 / 0.4 (dry grass N 0.5), cabbage 1 / 0.3 / 0.5, roots 0.3 / 0.5 / 1, fruiting plants and fruit trees 0.4 / 0.7 / 0.9 (cacao K 0.6), forest trees, palms, willows and cypresses 0.6 / 0.8 / 0.5, bushes and ferns 0.6 / 0.5 / 0.5, desert plants 0.2 / 0.4 / 0.6, legumes 0.1 / 0.7 / 0.6, mushroom 0.8 / 0.5 / 0.4, lily pad 0.8 / 0.5 / 0.3. `Available` and `Feed` read each species' values from a plain array (`speciesSoil`) and work in doubles: they run for every plant every step, and written with properties and `Math.Min` on floats they doubled a step's cost (Mono works float arithmetic out through doubles, and its float `Math.Min` is slow). `SoilTests`. Fertilizers will come later. Before, the soil was one fertility per cell (60 % climate, 40 % random patches); the balance notes below that speak of fertility date from then.
- A block column holds at most one plant. Nothing sprouts in a column `Ecosystem.BlockColumn` reserved (placed storage; not saved, `StorageSync` sets them again at start; checked first in `TryAdd` and `TryPlaceGrownPlant`, drawing nothing at random, so without storage nothing changes). `Species.Spacing` only applies between plants of the same species. A plant dies, at the next step, if the block under it is no longer one of its grounds or if a block is placed where it stands.
- **Water plants** (`Species.Rooting`, `SpeciesAsset.rooting`): `Dry` (most: the base is air above the ground), `Flooded` (the base is a water block on the bed of water exactly one block deep, with air above: `LilyPad`) or `Either` (`Cypress`). `Ecosystem.PlantBaseAt` finds the base in a column (seeds, commands' grown plants and birds' seeds alike), `HasGroundAndRoom` checks it; `Grounds` are then those of the bed. Filling the pool or covering its water kills the plant at the next step, like any change in its column. A `floatsOnWater` species (`SpeciesAsset`, display only) is drawn at the water's surface (`PlantRenderer` raises its foot by `ChunkMesher.WaterSurface`). `WaterPlantTests` cover shallow and deep water, land, either way, a filled pool, a covered pool and lilies spreading only over shallow water. This is not re-read every step: the ecosystem listens to `World.BlockChanged` and only rechecks plants in columns that changed, so **a block changed without `World.SetBlock` would never uproot a plant**.
- `Step` cost is what limits time acceleration (about 6.5 ms for 49,000 plants and 3,000 animals on a 512 world in the Editor with the NPK soil; the code before it took 4.6–4.9 ms for 42,000 plants measured at the same moment, so about 20 % more per plant; Editor timings drift by up to 40 % from one hour to the next, so compare variants side by side). Plants live in an array sorted by id, looked up by binary search; keep the per-plant work in `Live` free of dictionary lookups and block reads. **Performance rules, all result-identical** (on a 1024 world at day 60, about 166,000 plants and 20,000 animals, a step went from 42 to 28.5 ms measured side by side; animals are most of what is left, about 1 µs each, mostly memory reads scattered over the per-column arrays):
  - **A removed plant stays in the array, marked** (`Age == RemovedAge`), until the next compaction (`RemoveDying` during a step, `CompactRemoved` before `Plants`, `Write` or the census read it, never during a step): shifting the array for every sapling grazed to death cost more than the rest of a step. **Every loop over `plants[0..plantCount)` must skip marked plants**; `IndexOf` does not find them.
  - Per-column species arrays beside the id arrays (`plantSpeciesAtColumn`, `animalSpeciesAtColumn`, the species plus one), written exactly where `plantAtColumn` / `animalAtColumn` are (`Append` / `Forget`, `AddAnimal` / `WalkToward` / `Kill`): spacing, shade, kin, prey, edible plants and territory are tested without looking the plant or animal up. Diets are flattened tables (`eatsPlant`, `eatsAnimal`) and per-species soil values (`speciesSoil`) and shade (`shadingSpecies`) arrays built in the constructor, so **a species must not change once an `Ecosystem` has it** (tests set theirs before).
  - `FindFood` and `FindKin` walk each ring of radius r only (8r columns, not the (2r+1)² square), **in the old order** (the whole first row, the two ends of each row between, the whole last row): the first column found wins, so the order is part of the result. `TryAdd` runs its cheap tests first (soil, spacing, then blocks); none of them draws at random, so the order changes nothing else.
  - A column's top, bed and wetness are one packed int (`columnInfo`, `ColumnInfo`), one memory read per move instead of three. `World.GetTopHeight` / `GetSurfaceHeight` skip empty chunks (`Chunk.IsEmpty`, a count of non-air blocks kept by `Chunk.Set`; `ChunkSerializer.Read` recounts) and read blocks directly (`WorldTests.ColumnHeights_MatchAScanOfEveryBlock`).
  - **`ReferenceRunTests`** pins the hashes of a 1,500-step run on a generated 256 world with species chosen to reach every branch (`TestSpecies.ReferencePlants` / `ReferenceAnimals`), player actions and a save and reload included: an optimisation must leave them unchanged. They change only with an intended change of behaviour (a rule, a constant, the save format, the terrain); then copy the new values from the failure message. To measure a variant, compile `git show <commit>:Assets/Scripts/Eco.Sim/*.cs` with `CSharpCodeProvider` (namespace renamed, `/optimize+ /nostdlib+`, referencing `Library/ScriptAssemblies/Voxel.Core.dll` and the Editor's `NetStandard/ref/2.1.0/netstandard.dll`), load the same `ecosystem.dat` bytes into both and step them alternately, comparing their `Write()` bytes.
- Plants are records, not GameObjects and not `NetworkObject`s. They have no collision: players walk through them.
- Species are data: `SpeciesAsset` (ScriptableObject in `Assets/Species`, durations in game days, plus the meshes and materials to draw) converted to `Eco.Sim.Species`. **Plants reference their species by index in `EcosystemSync.speciesAssets`**, so reordering or renaming species makes `ecosystem.dat` fail to load (a fresh ecosystem then replaces it). Species added **at the end** of the list keep saves loading (`Ecosystem.SavedSpeciesCount`, the species the save knew): `EcosystemSync` then sows the new ones as in a new world (`Ecosystem.Populate(attempts, firstSpecies)`), or they would never appear, since plants do not immigrate. A new world is sown with one attempt per species per 1,024 columns (`ColumnsPerInitialAttempt`; 4,096 attempts in a 512 world with the first 16 species, as before), four times as many for species that need water beside them (`WaterSideAttempts`: a world otherwise started with a single willow), and species that need shade last. The save also records the world's seed and generator version and is refused on any other terrain, since plant positions only make sense on the terrain they grew on. Balance lives in these assets.
- **Plant species live by climate** (`Species.Suitability`, `SpeciesAsset` "Climate and ground"): each has an ideal range of warmth and of wetness (0 to 1, Geography's temperature and humidity) and a tolerance past them; the product of both fits, the plant's **vigour**, is how often its seeds take and how fast it grows (`Plant.Vigour`, from `Ecosystem.VigourAt`, worked out per fertility cell at construction; not saved, recomputed on load). Each also has the grounds it grows on (`Grounds`: grass and dirt by default; pines also snow, acacias and dry grass also sand, cacti only sand) and may need water beside it (`NeedsWater`: reeds). The ten species, in `EcosystemSync.speciesAssets` order: `Oak` (mild, wet, rich soil), `Bush` (wide range), `Birch` (cool), `Pine` (cold, snow), `Acacia` (hot, fairly dry), `Poplar` (mild, wettest), `TallGrass` (wide range), `DryGrass` (warm, dry), `Cactus` (hot, driest, sand), `Reeds` (water's edge). Rabbits eat bushes and tall grass. Over 500 days on two seeds in a 512 world (about 41,000 plants, 2 ms per step), every species holds and each climate has its own cover: pine and birch where it is cold, dry grass, acacias and cacti where it is warm and dry, oaks, poplars and bushes where it is warm and wet, a mix in between; rabbits 760–950, foxes 100–150. **Dense forests** (since thinned, see "Forests and meadows" below): the forest trees (oak, birch, pine, poplar) were then given spacing 2, about half their fertility use and more seeds (acacias stay sparse, spacing 4), because the soil fed only about 3 grown trees per fertility cell: on seed 1 by day 100 there are about 50,000 trees among 62,000 plants (19 % of columns in the median 16 × 16 region, 40–60 % in the densest; mild wet land becomes continuous forest, dry land stays open), bushes fell from 3,500 to 1,700, and a step costs about 4.2–5 ms in the Editor (2.9–3 before). Over 500 days on seeds 1 and 2 in a 512 world (about 63,000–64,000 plants, 49,000–52,000 of them trees) every species holds, without extinction (from day 100, seed 1 / seed 2: rabbits 298–480 / 250–437, hares 358–472 / 324–426, jerboas 122–204 / 150–227, deer 46–111 / 30–141, reindeer 9–49 / 7–60, gazelles 5–51 / 15–104, foxes 55–86 / 46–99, wolves 11–32 / 24–66, bears 5–29 / 17–31, jackals 12–41 / 14–58, fish 394–650 / 1,308–2,049, ducks 127–283 / 154–354, herons 7–17 / 8–24, otters 9–16 / 10–22, crows 25–89 / 31–85, vultures 41–73 / 56–84, sparrows 42–73 / 44–87). Reindeer peak lower than before (60 at most), bears touched 5 on seed 1, and fish stay low on seed 1; none of these was compared with a run of the old values on the same seed.
- **Jungle and marsh plants**, appended to `EcosystemSync.speciesAssets` (indices 10–15): `JungleTree` (emergent trees 17–19 blocks high on buttress roots, hot ≥ 0.66 and wet ≥ 0.66, rich soil), `Palm` (hot, fairly wet, also on sand), `Fern` (forest floor, warm and wet, also on mud), `Willow` (weeping, mild to warm, wet, at the water's edge, also on mud; lives 60 days, see Willows below), `Cypress` (bald cypress, wet, at the water's edge, rooted in shallow water or on mud, clay and soil; spacing 4, since at 3 they hid the pools), `LilyPad` (floats on water one block deep over mud, clay, dirt, sand or gravel; spacing 2, some fertility use, or 12,000 of them crowded every shallow river and lake edge). - `EcosystemSync` mirrors `WorldSync`: named messages, server-authoritative. A joining player receives the existing plants in batches of 500 per network tick (resuming by plant id, which stays correct while plants are born and die), and every player gets, once per network tick, only the final state of plants that changed (a plant's growth is sent as one of `Plant.StageCount` stages, not continuously). Felling is done by hits (`MiningSync`, see Mining and felling); the last one calls `EcosystemSync.FinishPlant`.
- Animals (`Ecosystem.Animals.cs`) follow the same rules as plants: records in an array sorted by id, one animal per block column, all behaviour inside `Step` with the shared `SimRandom`. Each step an animal gets hungrier, seeks food when hungry (herbivores graze plants from the next column, which lose half their growth: a plant left with less than 0.1 dies, so browsed saplings die; a plant is only eaten from growth 0.25 and if no taller than the animal's `ReachHeight`, so deer browse young trees, not grown ones; predators catch prey next to them, half as often when the prey is taller than the hunter), otherwise joins the nearest of its kind if it is a herd animal (`Herd`) or wanders toward the best of three random places for its climate, and may breed when well fed, less often where its climate suits it less.
- **Animals collide with blocks** through `AnimalMoves` (`Eco.Sim`): they walk up to `MoveRange` columns per step, one column at a time in eight directions, climbing at most 1 block and dropping at most 3, never cutting diagonally past a block's corner, sidestepping obstacles but never turning back. So a wall two blocks high stops them (fences work). The server also refuses to place a block inside an animal (`Ecosystem.IsAnimalInside`, checked in `WorldSync`). The client's `AnimalViews` re-walks the same rules on its own world (only start and end positions are sent) so the displayed animal follows the ground and goes around walls; it cannot know the occupancy detours, which are harmless. Changing these rules changes the food chain balance: it was re-checked over 500 days on two seeds after they were introduced (rabbits 250–450, foxes 34–68 on a 256 × 256 world). Species are `AnimalSpeciesAsset`s (diet given as references to other species assets, resolved to indices by `EcosystemSync`).
- **Two rules keep the food chain alive; removing either brings back boom-and-bust or extinction**: `TerritoryRange` / `MaxNeighbours` stop an animal breeding when enough of its kind are nearby (without it herbivores multiply until they strip the plants, which then cannot reseed), and `MinDensity` lets newcomers arrive, at random columns whose climate suits the species, when it falls below a floor (counted over the land whose climate suits it). The current values were chosen by simulating 500 days on several seeds; re-run such a simulation before changing them (an `Ecosystem` can be built and stepped directly from editor code, no Play mode needed).

- **Pickup halo** (`PickupHalo`, on its own object in the scene, material `Assets/Materials/PickupHalo.mat`, shader `ECO/PickupHalo`): what a right click would pick up, if it is an arrow or a carcass still worth taking, gets a green halo. `PlayerController.HighlightPickup` finds it every frame with the click's own search (`AimedPickup`: the nearest of storage, log, arrow and carcass, in front of the aimed block) and fills `PickupHalo.Parts` with its meshes as drawn (`BowSync.CollectArrowParts` → `ArrowViews.CollectParts`, `EcosystemSync.CollectCarcassParts` → `AnimalViews.CollectCarcassParts`, the same `LyingPose` as the drawing); `PickupHalo` draws them again in `LateUpdate`, display only: an inverted hull (back faces only, pushed out along the normals by a width in world units, unlit, translucent, no depth write), a faint glow 0.055 wide then a bright rim 0.018 wide over it, pulsing gently. It inflates a copy of each mesh whose normals are averaged over the vertices at the same place (made once per mesh, a mesh that cannot be read is used as it is), so the flat-shaded boxes' faces do not come apart at their edges. - The new animals' models are generated by `Assets/Editor/AnimalModelBuilder.cs` (menu **Eco > Rebuild animal models**): a quadruped laid out from a few proportions (legs, body, neck, head, snout, ears, tail) plus features (antlers, horns, ruff, hump, flank stripe, saddle, a hopper's haunches and long feet, tail tip), written as parts, rig and gait into each `AnimalSpeciesAsset`, with one material per colour (`Animal<Species>_<Fur|Light|Dark|Accent>`). The rabbit was modelled by hand and is not in its table. **The fox and the deer come from sculpted models** (`Assets/Models/<Species>/`), turned into parts by `Assets/Editor/ModelAnimalBuilder.cs` (menu **Eco > Rebuild animals from models**, one `Spec` per species). The **deer** (`Deer.fbx`, 120,000 triangles, with its colour texture `Deer_Diffuse.png`): measured and built at 1.45 blocks long, then scaled up by `Spec.Scale` to 1.9 blocks (about 1.3 at the back, 2.4 to the antler tips; asset `height` 2.41, `width` 1.0, `strideLength` 1.3), its head (turned 38° aside in the model) turned forward before simplifying (`DeerPose`, fading out down the neck), simplified to about 3,600 triangles, its four legs cut under the belly (y = 0.52, pivots worked out as the middle of each cut; ears and tail too small to move), and coloured from the texture: each simplified triangle takes the colours of the original triangles it covers (`ColourField`, found by position since the texture coordinates do not survive the simplification), gathered into 6 tones by k-means (`GatherTones`), each tone a material `AnimalDeer_Tone<n>` written by the build. The **fox**, `Assets/Models/Fox/Fox.fbx` (a static low-poly mesh, no rig, no texture): scaled to 1.3 blocks long, simplified from 120,000 to 2,400 triangles (edge collapses by quadric error, which keep the silhouette), cut along planes (`FoxCuts`: behind the rump, under the belly, above the skull, so each moving part meets the body on one flat cut through its pivot, a clean hinge) and sorted by boxes in the animal's space into body, four legs, two ears and tail with their pivots, each cut closed on both sides by a cap (`AddCaps`: the mesh is hollow, so the crack a swinging tail opens would otherwise show through the animal), so the `Trot` gait animates it like the boxes, and painted by region with the fox's three materials (white throat, chest, belly and tail tip; black socks, ear backs and nose; then `SmoothColours` gives a triangle the colour that at least two of its neighbours in the same part share, which removes stray triangles and ragged edges), plus open eyes over the model's closed slits (`BuildEyes`: a dark almond and a glint per eye, each point projected onto the simplified surface and lifted a few millimetres off it), as flat-shaded meshes `Fox_<Part>_<Colour>.asset` in `Assets/Species/Models`. Each part also has a `shadowMesh` (`<name>_Shadow.asset`, the same surface with smooth normals) that casts its shadow instead: with flat-shaded facets, the light's normal bias moves each facet along its own normal in the shadow pass and the light leaked between them, riddling the shadow with holes. A part may thus be any mesh, not only the cube (`AnimalViews` sizes a carcass's body from the mesh's bounds; a part with a `shadowMesh` is drawn without shadow, and its shadow mesh into shadows only). Another model needs its own regions in that file.
- Animals are synchronised differently from plants: twice a second at most, each player (the host included) receives the complete list of animals within `plantViewDistance` + 32 blocks, and only when it may have changed. Animal models are lists of boxes in their `AnimalSpeciesAsset` (`parts`: the built-in cube, a material with GPU instancing, offset and scale; no rotation), with a parallel `rig` naming each part's motion (body, ear, front leg, hind leg, tail) and pivot; a part's side comes from its pivot's x (negative is left). Gaits: `Hop` (the rabbit), `Trot` (the fox: legs in diagonal pairs, one cycle per `strideLength`, the tail sways, also when standing), `Fly` (birds, see Birds) and `Glide`. Clients play each move between lists (`AnimalViews`), spread over about the time until the next list (`EcosystemSync.AnimalListSeconds`: one step at the current speed, but at least `AnimalFeedInterval`, since lists come at most twice a second). At speed 1 nearly every animal moves each step, but only by 2 or 3 columns in 10 s. So with time to spare the animal is shown **wandering around its destination** on the way (`AnimalViews.Route`): detours by columns (walked with `AnimalMoves.TryNextStep` on this machine's world, so they follow the ground and keep out of water or walls as the species' habitat requires), each a third of a turn or so around the destination at up to the species' `MoveRange` from it (and 4 at most, so the server's reach check for a strike still holds), until the way is about 40 % of the animal's pace times the time until the next list (`WanderPace`; a deer walks about 1.1 blocks a second, 11 blocks a step); an animal that stayed put wanders too, when its trip is nearly over. A walker then moves all the time (98 % of the time measured at speed 1), with strides shortened by the square root of its share of pace (so legs swing slower and less); if the detours are blocked and the way is short, it slows down, to 15 % of its pace at the slowest, and the time left is shared unevenly (from a hash of the animal and its destination, so a herd does not move as one) among pauses before each leg. A hopper's way is cut into one leg per hop (hops of `hopLength` lasting `hopDuration`, never stretched: spreading a hop over the step made a rabbit take seconds per hop) with short pauses between hops (a rabbit hops about every 0.75 s). A bird flies its wandering way for about 40 % of the time (`FlightShare`) at its pace, then perches. A move ends right at the next list (ending sooner stopped every animal at once). Before this, at speed 1 an animal walked its 2 or 3 columns at its pace (`walkSpeed` is a trot, 2.5–3.4 blocks a second) in 1–2 s and stood still for the rest of the step.
 A move longer than 1.25 times the time until the next list is quickened to fit: at high multipliers it covers several steps and the animal moves on without stopping (when a move lasted only one step, animals dashed then stood still until the next list). The way is smoothed (`AnimalViews.View`): corners rounded over 0.35 blocks on each side (a quadratic curve that stays within the corner's column, so no wall is cut; none where the animal pauses) with the facing following the curve, a turn at 360° a second when a move starts and at the end of a pause, legs that swing out and settle back over 0.25 s when the animal sets off and stops, and a move that interrupts another carries on the stride, an interrupted hop's height and a flight's height; birds climb and come down at about 4 blocks a second (a short flight stays low, and the rest of the way down is flown once there), and at high speed stay up between moves.
 **The displayed position can still lag the server by up to one simulation step** (at high speed, by the steps of up to about 0.6 s); the server's check of an arrow's hit (`EcosystemSync.TryWoundAnimal`) allows for one step (`MoveRange`) plus a block. `PlayerController` strikes whatever is nearest along its ray through `EcosystemSync.TryStrike` (a plant, else a block; an animal is never struck, only shot: see Tools).

- **Chunk meshes** (`ChunkMesher`, `ChunkMeshBuilder`, `ChunkMeshing`): a `ChunkMeshBuilder` works a chunk's mesh out into its own buffers, reading only the world and the sky light (so on any thread while nothing changes them), and `ApplyTo` hands it to a `Mesh` (main thread). `ChunkMeshing.BuildAll` builds batches of chunks on every core (`Parallel.For`) while the main thread applies the previous batch; `VoxelWorld` uses it when a world is shown and when 16 chunks or more are dirty at once (a client receiving modified chunks), else one builder on the main thread. **Only chunks with faces have an object** (about 8,300 of the 32,768 of a 1024 world: the rest are air or buried rock; a chunk that gains faces gets one when remeshed, one that loses them keeps it). Meshes keep no copy of their data on the CPU (`UploadMeshData(true)`, several hundred MB for a whole world), so they cannot be written again: a remesh makes a new `Mesh` and destroys the old one; nothing reads chunk meshes back (collisions and rays use the world). `ChunkMesherTests` pins a hash of every chunk mesh of a generated 128 world (it changes with `TerrainGenerator.Version` or the mesher's output) and checks worker threads against the main thread; all 32,768 meshes of a 1024 world were compared with the single-threaded mesher before the change. `World.Generate` fills chunks in parallel for an `IParallelChunkGenerator` (`TerrainGenerator`: its `Generate` only reads what `Prepare` worked out, and writes its own chunk; `WorldTests.ParallelGeneration_GivesTheSameBlocksAsOneChunkAfterAnother`).

The server (`Bow.Shoot`) checks the shot leaves the shooter's eyes and they own a bow, takes an arrow, works the flight out on its world and shows it to the others (`Bow.Shot`); the shooter then says what it hit (`Bow.Landed`, or after 10 s it is taken as a miss), the server checks the animal was within its `MoveRange` plus a block of the flight (`EcosystemSync.TryWoundAnimal`) and deals 10 × the draw, doubled in the head (`Ecosystem.Damage`). **The shooter sees the damage dealt**: their machine keeps where each of its arrows was seen to hit (`BowSync.hitPoints`, by shot), the server answers an accepted hit with `Bow.Hit` (shot, damage, head and killed flags; the host directly), and `HudBanner.ShowDamage` shows "-10", "-20 Head", "-10 · Killed" rising 0.8 block from that point over 1.2 s, popping in and fading out (labels in the `damage-numbers` layer of `Hud.uxml`, placed every `LateUpdate` with `RuntimePanelUtils.CameraTransformWorldToPanel`, hidden behind the camera; `.damage-number` in `Hud.uss`: light red, gold and larger in the head, red when it killed). It cannot check the head (it does not know which way animals face): it believes the shooter. **An arrow that hits is lost in the animal** (it is never laid down); one that misses lies where the server's flight stopped (`Bow.Added`). A killed animal's carcass falls **where the shooter saw it**: `Bow.Landed` also carries the column it was shown in (`AnimalViews.TryHitArrow`'s feet; clients show animals wandering up to their `MoveRange` from their column), accepted within `MoveRange` plus a block of the animal's column (`WoundFleeSteps` plus one for `RunShownSeconds` after it fled, while clients may still show it running), else in its own column (`Ecosystem.Damage(id, amount, fallX, fallZ, fallRange)`), so it does not jump away when it dies. A wounded animal that lives **runs off** (see Fleeing below); **An arrow may break when it lands** (`ArrowBreakage` in `Voxel.Core`, `ArrowBreakageTests`; drawn by the server with its own `System.Random`, not the simulation's): 10 % on soft ground (one hit to break), 20 % on gravel, clay or ice, 35 % on rock, ores and bedrock (by `MiningRules.HitsToBreak` of the block that stopped it, `ArrowFlight.Trace`'s `stoppedBy`); a broken arrow lies nowhere: the server sends `Bow.Broke` (point, face normal, whether it is yours) and every machine throws splinters of the shaft's colour (`ChipBursts` with `Chips.mat`, 8 at 0.45 of a block chip's size), the shooter reading "Your arrow broke" above the hotbar; arrows lying in the world are kept by the server, saved with the world in `arrows.dat` (`BowSync.Save`, with the other saves), sent to joining players (`Bow.Arrows`) and picked up with a right click within reach if the player can carry them (`Bow.Pickup`, `Bow.Removed`). They are drawn as three boxes (shaft, head, fletching; `Assets/Materials/ArrowShaft.mat`, `ArrowHead.mat`, `ArrowFletching.mat`, instanced). Bare hands on an animal only say "You need a bow to hunt": the old one-hit kill (`Eco.Kill`) is gone.
- **Fleeing** (`Ecosystem.Flee`, `EcosystemSync.MakeFlee` / `ScareAnimals`, `AnimalViews` runs, `AnimalHealthTests.AFleeingAnimal_RunsStraightAwayFromTheThreat`): an animal runs off from players. `Ecosystem.Flee(id, fromX, fromZ, steps)` walks it up to `steps` columns straight away from the threat (`WalkToward` toward a point twice as far, so it goes round obstacles and keeps its heading; habitat, climbing and occupancy as in any walk), a player action between steps that draws nothing at random. The server makes a wounded animal that lives flee `WoundFleeSteps` = 10 columns from where the arrow was shot (the path's first point), and, every `ScareInterval` (0.25 s), every animal that hunts no other animal (`AnimalSpecies.EatsAnimals` empty: grazers, birds, fish, frogs; not foxes, wolves, bears, jackals, jaguars, crocodiles, herons, otters) within `ScareRadius` = 6 blocks of a player flee `ScareSteps` = 6 columns from them, at most once per `ScareCooldownSeconds` (1 s). `fledAt` keeps when each fled (real time, forgotten after `RunShownSeconds`); for `FleeFlagSeconds` (1 s) the animal lists mark it as fleeing (a flag byte after each animal's position, `AnimalEntrySize` 4 ints and 2 bytes), and `AnimalViews.Add` then plays its move straight to the new column (`Route` with no wandering) at `FleeSpeed` = 1.6 times its pace without pauses (`View.SetTrip`'s `runSpeed`, ending at `runEnd`; no wandering trip cuts a run short, `IsRunning`). The next simulation step goes on as usual (a herd animal walks back to its kin). Only the host was tested, not a remote client.
- **Tools in hand**: the tool in the chosen hotbar slot shows in the player's right fist, for everyone. The owner's controller calls `PlayerModel.SetHeldItem` every frame, which writes an owner-writable `NetworkVariable<int>` (`heldTool`, `Items.None` for anything that is not a tool) only when it changes; each machine puts a `Tool` object under the right forearm (`ShowTool`). Its mesh is made once per tool from `ToolShapes` (`Voxel.Client`: the boxes of each tool and of the arrow) by `BoxMesh` (flat-shaded boxes, a submesh per material, also used by `ArrowViews`), at 0.7 of their size, gripped at `ToolShapes.GripHeight` (a shovel near the top of its handle, turned end over end so its blade is ahead), tipped to point ahead and about 40° up (`ToolTilt`), the axe's, pickaxe's and bow's heads turned into the plane of the swing (`TurnInHand`). Materials are `toolWood` / `toolIron` / `toolLight` on `Player.prefab` (the arrow's three materials). With a tool, the right arm swings half as much, is raised 15° and its elbow bent 45°. The owner sees it at the bottom right of its view.
- **Mining and felling** (`MiningSync`, rules in `MiningRules`, `HitPacer`, `MiningDamage` in `Voxel.Core`, `MiningRulesTests`): one left click with the right tool is one hit, at most one a swing (`MiningRules.SwingInterval`: 1/3 s; a starving player cannot swing at all, see Hunger; a click during a swing is kept 0.25 s, `PlayerController.Strike`). Blocks take hits by hardness (`MiningRules.HitsToBreak`): dirt, grass, sand, snow, mud, tilled soil 1; gravel, clay, ice 2; limestone, sandstone, slate, rock salt 3; granite, marble, basalt, flint 4; coal, iron, copper, tin ores 5; gold 6. A tree takes 4 axe hits per wood of its size (`MiningRules.HitsToFell`, `FellingHitsPerWood`, 8 to 32: an adult oak 16, a jungle tree 32; its wood is `WoodYield × PlantShape.Scale(stage)`, `MiningRules.WoodOf`), a plant without wood one scythe cut, a stump 3 shovel hits. Damage shows as cracks (4 stages, `CrackViews`: a cube 1.006 times the block, alpha-clipped `Assets/Materials/Cracks.mat`, textures painted at start) and wears off when left alone (one hit lost every 1.5 s after 5 s). A tree being felled shows a **notch** in its trunk (`NotchViews`, drawn by `MiningSync` for every machine): a wedge on the side the last hit came from (the point carried by `Mine.Hit` / `Mine.Struck`), its floor at the stump's cut height (`PlantShape.StumpHeight`) and its upper face at 45°, as deep as the share of hits taken times 0.6 of the trunk's thickness, shrinking back as the damage wears off. The trunk there is found from the stump model's cut disc (`PlantRenderer.TryGetTrunk`, via `EcosystemSync.TryGetTrunk`: the disc is the widest trunk box at that height, at 0.92 of its width), so only species with a stump get one. Since the trunk is an instanced mesh that cannot be hollowed, the notch is pale wood laid 0.008 over the bark and lit like it (the stump's `PlantStumpCut` material over a grain texture painted at start): the opening on the front (light floor, dark line at the back, shaded sloping face, all painted) and the wedge's profile as a triangle on each side. Each hit swings the arm and tool for everyone (`PlayerModel.Swing`, an owner-writable `NetworkVariable<byte>` counter; a chop to the impact at 0.06 s, then back up past the holding pose) and throws chips of the block's face colour (`BlockAtlas.ChipColour`) or the plant's bark (`ChipBursts`, instanced cubes with gravity, `Assets/Materials/Chips.mat`). **Messages**: the hitter's machine shows the hit at once (and a block's break on its last hit, `WorldSync.PredictBreak`; a one-cut plant's removal; never a tree's fall) and sends `Mine.Hit` (a block with the type it saw, or a plant id, the point and face); the server checks the pace (`HitPacer`, by server time, two hits bunched by the network accepted), reach, that the block is still what was seen, the tool owned and room for the drop, counts the hit (`MiningDamage`, never saved), burns its calories, sends exactly one `Mine.Struck` to the hitter (accepted or not, with the hits that count: it shows them plus its own unanswered ones) and one to every other player (to show cracks and chips), all on the reliable ordered channel of `WorldSync`, then on the last hit breaks the block (`WorldSync.TryBreak`) or finishes the plant (`EcosystemSync.FinishPlant`). A refused hit sends the real block back (`WorldSync.SendRealBlock`) or the plant (`EcosystemSync.RestorePlantTo`). **A felled tree falls**: `EcosystemSync.FinishPlant` sends `Eco.Felled` (the plant, its view and the direction away from the player) to the others and plays it on the host; every machine draws the fall (`PlantRenderer.StartFall`: about its foot above the stump, 90° in `FallSeconds` = 1 s, a small bounce, then it shrinks away) and shows the stump at once. The tree becomes a **stump** if its species has one (`SpeciesAsset.HasStump`), else it is removed (cacti). Its seeds (one if adult, two 35 % of the time, `MiningRules.SeedsFromFelling`; none if young) and crop (if ripe) go into the inventory, what fits; its **wood lies on the ground as logs**, one per wood of its size, each worth `MiningRules.WoodPerLog` = 3 wood when picked up (all three or none, so a log is picked up only with room for three) (`LogSync`, `LyingLogs` and `LogPlacement` in `Voxel.Core`, `LyingLogsTests`): spread along the fall from past the stump to the tree's height, each on its column's top (afloat on water), piled where a wall more than a block high stops the line (`LogPlacement.AlongFall`), shown once the tree has fallen; a stump dug out leaves one log. Logs are saved with the world (`logs.dat`, magic "LOGS"; logs of an unknown species index are dropped on load), sent to joining players (`Log.All`), added (`Log.Added`, with the delay before they show), moved when a block changes under or into them (`LogPlacement.Settle`, `Log.Moved`) and picked up with a right click if the player can carry the wood, which is **that tree's wood** (`Items.WoodOf(log.Species)`) (`Log.Pickup`, `Log.Removed`). They are drawn by `LogViews` (two crossed bark boxes in their tree's bark material, pale ends in `PlantStumpCut`).
- **Stumps** (`Plant.IsStump`, `Ecosystem.CutToStump`, `StumpTests`): a negative `Plant.Age` (never `int.MinValue`, the removed mark) counting up to 0. A stump keeps its column, id, species and size (it is drawn at the tree's size), blocks its column and spacing, and does nothing else: in `Live` it neither ages toward death, feeds, starves, ripens nor seeds, and draws nothing at random; it gives no shade (`IsShaded`), is never eaten (`IsEdiblePlant`) nor harvested, and is left out of the census. After `Ecosystem.StumpRegrowSteps` (3 days) it sprouts a sapling of its tree (stage 1, same id), which lives a whole life. `ecosystem.dat` format 9 (the same layout as 8, which still loads) allows negative ages. On the wire the stump is bit 3 of a plant's stage byte (stage bits 0–2, `StageMask` 0x07; ripeness bits 6–7), `PlantView.Stump`; its aiming box is `PlantShape.StumpHeight` (0.6) high, the label says "Oak stump · needs a shovel", the maps draw no crown for it. Stump models (`SpeciesAsset.Model.stump`) are made by `PlantModelBuilder.StumpOf` for species giving at least 2 wood: the upright trunk boxes starting below 0.6, cut there (each cut a little lower than the last, so no tops are coplanar), with a disc of pale wood (`PlantStumpCut` material) over the cut.
- **Storage** (`StorageSync`, rules in `StorageRules`, `StockpilePiles`, `Storages` in `Voxel.Core`, `StorageTests`; window `StorageScreen`; drawing `StorageViews`, `ChestShapes`): three placeable items; a chest and a small stockpile are given once to every player with their tools (`PlayerState.ReceivedStorage`, players from before too; those who were given the large stockpile before keep it, and it is not crafted; chests and small stockpiles are). A **chest** (`Items.Chest`, 4 kg) stands in one cell on top of a solid block (`StorageRules.CanPlaceChest`) and holds any item that is not a block or wood, **by weight**, up to `StorageRules.ChestMaxWeight` = 150 kg (`ChestRoom`, like `CarryLimits.Room`); a **stockpile** (`Items.Stockpile`, 2 kg) covers 3 × 3 cells of flat solid ground (`CanPlaceStockpile`, placed in front of the player: `StockpileCorner`, the aimed cell in the middle of the near edge) and holds blocks and wood (`CarryLimits.CountsAsBlock`) in 9 piles of one type each, up to 27 per pile (243 in all; a pile takes another type only once empty); a **small stockpile** (`Items.SmallStockpile` 105, `StorageKind.SmallStockpile` 3, 1 kg) is the same on 2 × 2 cells, 4 piles of up to 20 (80 in all; `StorageRules.SideOf` / `PileCountOf` / `PileSizeOf` / `CapacityOf` by kind, `IsStockpile` for both; `StockpilePiles` takes its pile count and size, its `Count` / `PileSize`; placed from the aimed cell as the left one of its near edge, `StockpileCorner(target, facing, side)`; drawn with its own frame, a full pile two layers of cubes and two on a third; icon `SmallStockpile.png`; `storage.dat` unchanged, the piles follow from the kind). Placing is a right click with one in hand (`PlayerController`, which also draws where it would go, green or red, `StorageSync.ShowPreview`); the server checks ownership of the item, reach, the rules, and that no block, player, animal, plant (stumps included: "Something is growing there") or log stands in its cells nor other storage covers them. Each storage has its owner (the placer's player id), a list of allowed player ids and what it holds, saved with the world in `storage.dat` (magic "STOR", format 5: format 5 added carpentry tables, `StorageKind.CarpentryTable` 6, and each station order's choices and what was taken for it (`StationJob.Choices`, `Taken`; older orders take the recipe's items × stocked); format 4 added butcher's tables, `StorageKind.ButcherTable` 5, laid out as a campfire; format 2 added campfires, `StorageKind.Campfire` 4, each followed by its wood and queue (`Station.Write`), format 3 orders of several dishes (count and stocked in place of what was taken; a format 2 dish loads as an order of one); formats 1 to 4 still load; items that no longer exist are dropped). **Cells**: a chest's cell is always solid, a stockpile pile's when it holds something (`Storages.IsSolid`): players collide with them (`VoxelCollision.Move`'s `extraSolid`); no block is placed in any covered cell (`WorldSync.IsEditAllowed`, and the client first); the block under storage cannot be broken ("Something stands on it", `MiningSync.CheckBlockHit` and `PlayerController.Strike`); nothing sprouts in its columns (`Ecosystem.BlockColumn`). Rays (blocks, arrows) pass through storage. **Opening**: a right click on storage (`StorageSync.TryAimed`, a chest's box or each pile up to its height, at least the frame's) asks the server, which checks reach and access (`StorageSync.CanUse`: anyone while no cell of it lies on claimed land, a **public** storage, `StorageSync.IsPublic`, said by the aiming label "Chest · Alice · public" and the window's owner line "· public (unclaimed land)"; else the land's owner and the players they allow on their land, `Claims.CanAct` at its first claimed cell, `StorageSync.TryLandOf`; else "Not yours"; claiming the plot under a public storage makes it private at once, and its viewers' windows close). **On claimed land a storage is the land owner's**, whoever placed it, even before the claim (`StorageSync.OwnerOf`, worked out from the land, never saved: `Storage.OwnerId` stays the placer, who owns it again off claimed land; the aiming label and the window show the land's owner, `TryDescribe` through `ClaimSync.TryDescribe`). **The chests, and the stockpiles, of one claimed zone share what they hold** (`StorageSync.PoolOf`: the storage of that kind whose land is in the same `Claims.ZoneOf`, in id order; off claimed land a storage is its own pool; rules in `StoragePool`, `Voxel.Core`, `StoragePoolTests`): a chest pool is one chest of 150 kg a chest (deposits fill the chests in order, `AddToChests`; takes draw from them in order), a stockpile pool, large and small stockpiles together, all its piles one after another, each stockpile's after the last one's (`TryFindPile`, `StoragePool.Capacity`). The server sends the opener the pool (`Store.Contents`: whether it is theirs, then each member, `WriteMembers`: its id and kind, then a chest's items or a stockpile's piles; the client keeps them, `StorageSync.OpenedMemberList`, and adds a chest pool's up, `OpenedContents`); the window titles "In the chests (3)", gauges out of 150 × n kg or the stockpiles' summed capacity, and shows the pool **merged or each storage on its own** (`PoolView`, a toggle "Merged" / "Each one" shown when the pool has more than one member, kept for the session): merged, a chest pool's items added up or a stockpile pool's items added up (taken from every pile of them, `StoragePool.TakeFromStockpiles`); each on its own, a card per chest (its name, "This chest" for the one open, framed in copper, its position as a tooltip, its weight out of 150 kg, its items) or per stockpile (its piles, 3 × 3 or 2 × 2, each pile's count out of its own size; a stockpile alone always shows so). `Store.Move` carries the member (a storage id, 0 for the whole pool: a stack dropped on a card goes into that one, Shift + click and right click go to the pool) and whether it is a stockpile's item from every pile (`byItem`); the server checks the member is in the pool (`StorageSync.MoveWithin`); after a move every viewer of a member gets it again (`Changed(storage, pool)`), and after any change of claims (`ClaimSync.ClaimsChanged`, a server event) every viewer, since pools may have grown, split or changed owner. **Each storage's own access list no longer has any effect** (still read and written in `storage.dat`): the window's Access tab is gone, and the owner line's tooltip says access follows the land; the server keeps who has each storage open, sends them every change, closes it (`Store.Closed`) when they leave its reach (checked every 0.5 s), lose access or it is picked up, and forgets them on disconnection. Moves (`Store.Move`): deposit takes what the player has and the storage has room for (`TryConsume` then add; "Chest is full (150 kg)", "No room on the stockpile", "It doesn't go in there"), taking gives what the bag has room for (`InventorySync.RoomFor` / `Give`, else `TellFull`). The owner picks storage up (`Store.Pickup`; the item goes back to the bag) once empty, or once what it holds fits in the rest of its pool, where it is poured (`StoragePool.TryEmptyInto`, all or nothing; else "Empty it first"); **anyone may pick up a public storage** (off claimed land, so its own pool), which then goes into their bag (the window's Pick up shows for them too). **Every machine** knows each storage's place, kind, facing, owner's name, whether it is the local player's (`Store.All` to a joining player, `Store.Added`, `Store.Removed`) and, in `Store.State` (sent on change), whether anyone has it open and a stockpile's piles; all on `ReliableFragmentedSequenced`. Refusals come back as `Store.Refused` (`StorageRefusal`, shown above the hotbar). **Drawing** (`StorageViews`, no objects): a chest is boxes of planks with two iron bands and a clasp (`ChestShapes`, materials `ArrowShaft.mat` / `ArrowHead.mat`), its front toward where its owner stood (facing + 180°), its lid raised to 65° while anyone has it open; a stockpile is a low frame of planks just outside its cells and each pile's blocks as cubes of 0.3 (a third of a block), 9 to a layer, up to 3 layers, in the blocks' atlas tiles with the blocks' material (`VoxelWorld.BlockMaterial`, full sky light) or for wood in that species' wood material (`SpeciesAsset.WoodMaterial`: its bark's grain in its `woodColour`, so each wood has its colour), one mesh per stockpile rebuilt only when its piles change. The aiming label says "Chest · yours", "Chest · Alice", "Stockpile · Alice (35 / 243)". Icons `Chest.png` and `Stockpile.png` are rendered by `ItemIconBuilder` (`ChestShapes`, then a frame with piles of cubes); the items are in the Tools category, kind "Storage".
- **Claimed land** (`Claims`, `ClaimRules` in `Voxel.Core`, `ClaimsTests`; networking `ClaimSync`, on the `GameSession` object; map picture `ClaimLayer`): land is claimed by **plots** of `ClaimRules.PlotSize` = 8 × 8 columns, the whole height of the world, on a fixed grid from the world's corner (128 × 128 plots in a 1024 world); a named player holds at most `MaxPlotsPerPlayer` = 16, anywhere, and allows other players **by name** on all their land at once (`ClaimOwner.Allowed`, kept even with no plot). The server keeps them and saves them with the world in `claims.dat` (magic "CLAM", format 1, the grid's size, the owners with their access lists, then each plot's owner index; a file for another world size is ignored with a warning). **On a plot claimed by someone, only they and those they allow act** (`Claims.CanAct`; free land and the outside of the world are anyone's): the server refuses, with "Claimed by Alice" (`ClaimSync.Check`, `Claim.Refused`, shown above the hotbar), placing or breaking a block or torch (`WorldSync.TryApplyEdit`, `TryBreak`, also when the block holds a torch in such a plot: `WorldSync.CanBreakOnClaims`), tilling (`TryTill`), any hit on a block or plant (`MiningSync.CheckBlockHit`, `EcosystemSync.CheckPlantHit`, so no hit is wasted), harvesting, planting (`EcosystemSync.TryHarvest`, `TryPlantSeed`), placing storage (every cell of a stockpile, `StorageSync.Place`), picking up a log, an arrow or a carcass (`LogSync.Pickup`, `BowSync.Pickup`, `EcosystemSync.TakeCarcass`), wounding an animal standing there (`EcosystemSync.TryWoundAnimal`, which now takes the shooter: the arrow then lands as a miss) and `/spawn` there (`CommandSync`). The access list is built by `PlayerRegistry.AccessEntries` and drawn by `AccessListView` (rows `access-*`, styled in `Map.uss`; `AccessEntry`, its own file). **Shown**: `ClaimLayer` (made by `ClaimSync.Layer` when there is a display) is a texture of one pixel per column, each claimed plot tinted by relation (pale gold yours, green allowed, a hue from the owner's name for others, `ClaimLayer.ColourOf`) and outlined where it meets land that is not its owner's, redrawn only around changed plots and uploaded at most ten times a second, laid over both maps (`map-claims`); the full-screen map's **plot mode** (C, a key in its footer) frames the plot under the pointer (`map-claim-hover`), replaces the layers list by the land panel (`land-panel` in `Map.uxml`: "n / 16 plots", what a click would do there, refusals, the access list), and a click (a press moving under 8 px, so dragging still moves the map) claims a free plot or releases one of the player's (`ClaimSync.RequestToggle`); outside plot mode the footer adds whose land the pointer is over. The HUD banner's place says "Meadow · Your land" / "Meadow · Alice's land" (`HudBanner.LandOf`) and the aiming label "Granite · claimed by Alice". **In the world** (`ClaimOverlay`, on its own object in the scene, display only): the ground of each claimed plot within 80 blocks of the camera tinted in its owner's colour (`ClaimLayer.ColourOf`), down the sides of its steps too and on water's surface, with a brighter strip along its edges where it meets land that is not that owner's; one mesh per plot, made again when a block changes in or beside it or the plot changes hands (`ClaimSync.PlotChanged`), drawn with `Assets/Materials/ClaimOverlay.mat` (`ECO/ArrowPreview`, white, vertex colours). Shown or hidden with C while playing (a HUD hint, "Claimed land shown (C)" above the hotbar) or with the toggle in the map's plot mode (`land-show-world`); `ClaimOverlay.Shown`, kept in PlayerPrefs (`showClaims`). There is no admin override nor expiry of an absent player's plots yet.
- **Planting** (`InventorySync.Plant` → `EcosystemSync.TryPlantSeed` → `Ecosystem.TryPlantByPlayer`, `PlayerSowingTests`): a right click with a seed on the ground. **Tree seeds** (species giving wood, `EcosystemSync.IsTree`) are planted by anyone, straight into a ground the species grows on (no tilling); **crops** only by gardeners, on tilled soil ("Only gardeners can plant crops", "Crops only grow on tilled soil: use a hoe", checked by the client first). - Block types (`Blocks`, 0–25 and 32–73; see also Wood blocks and Doors above: planks 35–53, logs 54–72, the door 73, `Blocks.LastType`; types stay below 100, where the item ranges begin): air, granite (`Stone`), dirt, grass, water, ice, five more rocks, sand, snow, gravel, clay, seven ores, bedrock, mud (32, the marshes' ground: the first type after the retired gap), tilled soil (33, made by a hoe) and the torch (34, the only oriented type; see Torches). **Types 4–6 and 26–31 are retired** (the crafted blocks: planks, bricks, timber frame, cut rocks) and never reused: `Blocks.IsRetired`, they are not valid blocks or items, `ChunkSerializer.Read` turns them into air and `Inventory.Read` drops them, so old saves still load. **Block textures are files**: one image per tile in `Assets/Resources/Blocks` (`BlockAtlas.TileNames`: `Granite.png`, `GrassTop.png`, `GrassSide.png`, `CoalOre.png`…, 24 tiles, then 57 for the wood blocks; adding one moves every texture coordinate, so `ChunkMesherTests`' pinned hash changes with it), read at startup by `BlockAtlas.CreateTexture` (`Resources.Load`, so they go into builds without references) and gathered into one row of square tiles; `BlockAtlas` maps each type to one tile (`TypeTiles`; grass has a top, sides and dirt below). The files can be edited or replaced at any size: tiles take the size of the largest file (rounded up to a power of two) and smaller ones are scaled up pixel by pixel; a missing file is drawn as a magenta checkerboard with an error in the console. `BlockTextureImport` (an `AssetPostprocessor` in `Assets/Editor/BlockTextureBuilder.cs`) gives every file dropped there its import settings (readable, uncompressed, no mipmaps, point filtering). A tile's **tint mask** is a second file, `<name>_Tint.png` (only grass has one): where it is white the pixel takes the climate's grass colour, so those pixels are drawn light grey in the tile itself; a mask rather than the PNG's alpha, since image editors often lose the colour of fully transparent pixels. The map colour of a block (`BlockAtlas.MapColour`) is the mean of its top's tile (grass and water have their own). The starting files were painted by code, now in `Assets/Editor/BlockTextureBuilder.cs` and `BlockTextureBuilder.Rocks.cs` (menu **Eco > Write missing block textures**, which writes only the files that are missing, so edited files are never overwritten: delete one to get its painted tile back). Soils and ice use pixel noise for grain (a ragged lower edge to the grass band). The rocks (granite, basalt, limestone, marble, sandstone, slate, gravel, bedrock, the ores, rock salt, flint), mud (dark lumps, a few pebbles and greyish puddles with a sheen on their upper left edge; note that `Fbm`'s `period` is the number of cells across the tile, so a smaller one is coarser) and snow (drifts and wind ripples, sparkles; bluish, never pure white, since a whiter snow saturates to a flat pink under the bright warm sun) are drawn like pixel art: each pixel's shade is picked from a palette of 3–5 shades per rock (`Ramp`, with 4 × 4 Bayer dithering between shades), from a tone that follows the rock's structure (Voronoi cells for crystals, columns, plates, pebbles and ore crystals gathered in veins; fBm smooth noise for beds and the turbulence of marble veins) and from a relief lit from the upper left (`RockHeight`). Every pattern wraps around the tile, so it runs on across blocks. To preview the atlas, call `BlockAtlas.CreateTexture` and blit it to a `RenderTexture` (the texture is not readable). Its mipmaps are made tile by tile (`BlockAtlas.HalveTiles`, down to 4 × 4 tiles) so that no colour bleeds between tiles: with point filtering, blocks stay sharp up close and do not shimmer far away. New block types need a tile (a constant and a name in `BlockAtlas.TileNames`, `TileCount`, its file, and its painting in `BlockTextureBuilder` if it should have a generated start), a name in `Items.NameOf`, and `Blocks.LastType` updated (it bounds what the server accepts from clients and what a save may contain).


Scale (measured in the Editor at the planned final size, 64 × 8 × 64 chunks = 1024 × 128 × 1024 blocks, `-worldsize 64,8,64`): the host starts in about 4.5 s and uses about 1.5 GB; a dedicated server starts in under 1 s and uses about 600 MB; sending the whole world to a joining player is 2.6 MB in under 6 s, and that player is in game after about 8 s; a mature forest was then about 85,000 plants. Those figures predate client-side generation: a joining player now receives only modified chunks. Still not done at that size: per-player chunk subscriptions (every client holds the whole world) and sending plants only near each player (every client receives every plant change). With empty chunks left without objects, meshing on every core and parallel generation, a host's 1024 world (seed 1, new) is ready in about 5 s in the Editor (filling the chunks 0.85 s after a landscape of 1.2 s, sky light 0.9 s, meshing 2 s), against 7.5–9 s before; a step at day 60 costs about 28 ms (166,000 plants, 20,000 animals; see the performance rules above). Measured again with the jungle and marsh species, before the forests were thinned (seed 1, Editor; with the thinner forests a 512 world has about half the plants, so expect about 140,000 plants and a cheaper step, not measured): the world is ready in 7.5–9 s (sky light 0.7 s, meshing 5.5–6 s), the Editor allocates about 2 GB; by day 60 there are about 260,000 plants and 17,000 animals and a step costs about 25 ms (so one step per frame at most when accelerated: `EcosystemSync` stops at its 8 ms budget after the first step); the game itself takes about 13 ms a frame (scripts 3–4 ms, plants and animals drawn in `LateUpdate` 7.5 ms, the camera 1.7 ms), but the Editor ran at 17 fps, most of the frame going to drawing the Editor's own UI (`UIR.DrawChain`, 54 ms). The landscape takes about 1 s. In that 1024 world, of the land: jungle climate 6.5 %, marsh 9.3 %, desert 3.7 %, cold 28 %, snow 8 %; water is 30 % of the world (17 % at 512).

Localization (`Loc`, `LocTable`, `LocalizedDocuments` in `Voxel.Client`; `LocTableTests`):

- **English is the language of the code and its own key**: every player-facing text is written in English where it is used and shown through `Loc.T(english)` or `Loc.T(english, values)` (`string.Format` with `Loc.Culture`, so numbers read "26,3" in French; `Loc.Number`). Each other language has a table, `Assets/Resources/Localization/<code>.txt` (`fr.txt`): one `English<TAB>Translation` per line, `#` comments, `\n` for a line break; a text missing from the table is shown in English. A text one English word cannot tell apart has a `context|English` key (`Loc.In("produce", "Strawberry")`, `eyes|`, `hair|`). `LocTable.Parse` reports lines without a tab and duplicate keys (the first is kept).
- **Names in sentences**: species, items and biomes go through `Loc.Name` (translated) and `Loc.Lower` (lower case). Templates about a name get `{0}` its translated name, `{1}` the same in lower case, `{2}` the English with its article ("an oak"), `{3}` the same capitalized (`ItemCatalog.WithName`, `SowRefusal`, `PlayerController.MissingToolMessage`, `TargetLabel`); a translation uses whichever its grammar needs ("Graines de {1}"). In French, formatted texts elide "de", "le", "la" before a vowel ("d'avoine"; not before h: "de héron").

Screens that write texts themselves listen to `Loc.Changed` and write them again (inventory categories, carry gauges, stomach, map layers `SpeciesPanel.Retranslate`, plant names in `EcosystemSync.TryAim`, rebuilt when `Loc.Language` changes).
- **The server sends English (or codes)**, never translated text: each client translates what it shows (`HotbarHud.ShowMessage`, `CommandConsole.AddLine`, refusals, `GameSession.SetMessage(english, values)` which logs in English). Command replies with values stay in English.
- **The language** is the one chosen in the main menu's Options (`MainMenu`, view `view-options`, `Loc.SetLanguage`, PlayerPrefs key `language`), else the computer's if it has a table, else English. To add one: write `<code>.txt` and add it to `Loc.Languages` (code and its name in itself); `LocTableTests` checks the French table reads cleanly and every line formats with four values.

Networking (Netcode for GameObjects 2.x, Unity Transport, direct IP; the UDP port is set on `GameSession` in the scene, currently 50000):

- `GameSession` owns starting and stopping, in three roles: host (`-host`, or the main menu), client (`-connect <address>`, or the main menu), and dedicated server (`-server`, implied by `-batchmode`). F10 leaves. Screens drive it only through its public API (`Host`, `Join`, `Leave`, `Quit`, and the state `InMenu` / `IsConnecting` / `IsLoading` / `LoadingProgress` / `Message`, the last problem to show). Other arguments: `-port`, `-password`, `-data <dir>` (server save folder, default `Application.persistentDataPath`), `-autosave <seconds>`, `-playerid <id>`, `-worldsize <x,y,z>` (size in chunks of a new world, overriding the scene), `-seed <number or word>` (seed of a new world), `-noupnp`.
- **Dedicated server**: the Dedicated Server build module is not installed, so the server is the normal player run headless. `VoxelWorld` skips all meshing and rendering when `Application.isBatchMode` is true, the frame rate is capped to the network tick rate, and the process quits if the server stops.

```powershell
& "A:\dev\ECO 2\Builds\Test\ECO2.exe" -batchmode -nographics -server -password secret -data "D:\eco-server" -logFile "D:\eco-server\server.log"
```

- **Router port forwarding (UPnP)**: when a server or host starts, `GameSession` asks the home router to forward the UDP port to this machine (`PortForwarding` / `UpnpGateway` / `UpnpProtocol` in `Voxel.Core`, written by hand: no library), renews it every hour and removes it when the session ends. It is best effort: the result is one log line starting with `Internet:` (also shown on the host's screen), and a refusal never stops the server. All router calls block, so they only run on background tasks; on quit the removal is waited for (up to 4 s). Disable with `-noupnp` or the `openRouterPort` checkbox. **Pass `-noupnp` to servers launched for testing**, so tests never change the user's router. The tests use a fake router on localhost. Everything a router sends is treated as untrusted (description and control URL must be on the device that answered, DTDs refused, answers capped in size). UPnP cannot help when the router has no public address (the summary says so) and does not open the Windows firewall.
- **Server role teardown differs from client teardown**: a dedicated server never raises `OnClientStopped`, so `GameSession` ends a session on both `OnServerStopped` and `OnClientStopped` (a host gets both; `sessionActive` makes it idempotent).
- `PlayerRegistry` (server only, plain class created by `GameSession`) is the connection approval callback. It checks the password (empty = open server), refuses a player id that is already connected, and spawns the player at the position saved in `players.dat`, raised out of any block built there since. A client's id comes from `PlayerIdentity` (a GUID file in `persistentDataPath`; **the Editor uses a separate file from builds** so both can join the same server from one machine). The id and password travel in the NGO connection payload (`ConnectionRequest`), unencrypted.
- **Saving happens on the server only** (`world.dat`, `players.dat`, `ecosystem.dat` in the data folder): every `autosaveInterval` (60 s), when a player disconnects (players only), on F10 and on quit. **A player's object is already unreadable when NGO reports the disconnection or the end of the session**, so `PlayerRegistry.TrackPlayers` records every connected player's position each frame. `GameSession.EndSession` saves everything once more before tearing the session down, because on quit the network can stop before `OnApplicationQuit` reaches `GameSession`. A killed server loses at most one autosave interval.
- The client shows the server's refusal reason only when it is one of the texts in `ConnectionRefusal` (`Voxel.Core`); any other `NetworkManager.DisconnectReason` is NGO's internal wording and is replaced by a generic message.
- The server's world is persistent (loaded from and saved to `world.dat`). **A client never reads or writes a world file**: it generates the terrain itself from the server's seed, and `WorldSync` then receives only the chunks modified since generation.
- `WorldSync` uses NGO named messages, not RPCs or `NetworkVariable`s, so it needs no `NetworkObject`: on connection, world info (size, seed, generator version, `World.TerrainFingerprint`, number of modified chunks), then the modified chunks (`ChunkBatch`, one batch of at most 16 KB per client per network tick, nearest first), then one message per block change. The client generates the world inside the world-info handler, so later messages always apply on top of generated terrain. If its generator version or terrain fingerprint differs from the server's, it leaves with `WorldSync.Failure` set (shown in the menu) rather than play on mismatched terrain. Chunks are serialized when sent, and all these messages share one reliable ordered channel, so a block changed during the transfer is never lost. Every client currently receives the whole world and every change; per-player chunk subscriptions are left for the load test.
- `PlayerRules` (`Voxel.Core`) holds the player size, eye height and reach used by both the local simulation and the server checks.
- The server chooses each player's spawn position in `GameSession.ApproveConnection` (connection approval is enabled for that reason). Scene management is disabled in the `NetworkManager`: there is a single scene and a reload would destroy the loaded world.
- `Assets/Prefabs/Player.prefab` is the player prefab. Its `NetworkTransform` is **owner-authoritative**; `PlayerController` is a `NetworkBehaviour` that stays disabled except on the owner, which simulates movement locally. The scene's Main Camera is not parented to the player; the owner repositions it every frame.
- The player's body is built at runtime by `PlayerModel`: eleven joint pivots (hips, spine, head, shoulders, elbows, thighs, knees), each carrying one mesh of boxes (head with hair, nose and ears; chest with straps and backpack; shin with shoe; forearm with hand), textured by `PlayerSkin`, a runtime texture of 32-pixel tiles like the block atlas; `Assets/Materials/Player.mat` only supplies the shader settings. On side faces the tiles run from back to front on both sides. Its animation (walk with knee and elbow bends, jump, idle breathing) is procedural and **derived from how the player object moves**, so remote copies animate from the `NetworkTransform`. The one extra value on the network is the gaze pitch: `PlayerController.Look` calls `PlayerModel.SetLookPitch`, which writes an owner-writable `NetworkVariable<sbyte>` in whole degrees only when it changes; the head follows it up to 70° and the chest does not. **The owner's camera sits at the eyes of that head** (`PlayerModel.EyeOffset(pitch)`, used by `PlayerController.PlaceCamera`): the head turns about the neck, so looking down moves the camera about 0.21 forward and 0.2 down, in front of the chest and still inside the collision box. That is what lets the owner see its own body; only the owner's head joint (which also carries the neck) is hidden, as a shadow caster. `PlayerRules.EyeHeight` is still what the server uses for reach checks. The shirt colour comes from the NGO client id, so it can change from one session to the next.
- **Appearance** (`Appearance` in `Voxel.Core`: sex, skin tone, eye colour, hair style, hair colour, facial hair, one 16-bit code where 0 means "not chosen"; **all 16 bits are now used**, so another choice needs a wider code, a new `players.dat` format and a wider `NetworkVariable`; colour index 0 is the colour everyone had before colours were added, so codes saved without them keep their look; the colours themselves are in `PlayerSkin`, their names in `Appearance`) is chosen once, at a player's first connection, in `AppearanceMenu`, and kept in `PlayerState` (`players.dat` format 3 and later; older formats load with no appearance, so those players get the menu once). The server writes it into an owner-independent `NetworkVariable<ushort>` on `PlayerModel`, set in `OnNetworkSpawn` from `AppearanceSync.StoredCode` so clients never see the default first (the host's own player spawns before `AppearanceSync.StartServer`, which then publishes it). A choice is sent with the `Look.Choose` named message and refused once one exists. `PlayerModel` rebuilds its meshes and texture whenever the appearance changes (`Preview` does it locally while choosing). While the menu is open, `PlayerController` freezes the player and puts the camera in front of it, and the head is shown. Dragging beside the panel turns the body with `PlayerModel.SetPreviewYaw`, which rotates only the local model (not the player object, so nothing is sent); it is reset when the menu closes. **Names** (`PlayerNames` in `Voxel.Core`: 2 to 16 letters, accented ones too, digits, single spaces, `_` or `-`, unique on a server ignoring case, `PlayerStore.IsNameTaken`): chosen in the same menu, a field above the appearance (Confirm stays disabled while it is invalid), sent with `Look.Name` (`AppearanceSync.RequestName`), checked by the server, kept in `PlayerState.Name` and shown to every machine through a server-written `NetworkVariable<FixedString64Bytes>` on `PlayerModel` (`PlayerName`, set at spawn like the appearance); a refused name (`Look.NameRefused`: "Name taken", or the rules) brings the menu back with the reason, with the name alone if the appearance went through. A player who has an appearance but no name (a save from before names) gets the name alone once. Names show in storage access lists and labels, **over the other players' heads** (`Nameplates`, run by `HudBanner.LateUpdate` in the `nameplates` layer of `Hud.uxml`: a pill `.nameplate` placed every frame 0.45 above each head, for every spawned object with a `PlayerModel` but the local player, fading out from 32 to 48 blocks, hidden behind the camera or when a voxel ray from the eye meets a block first; none while the player has no name) and **on both maps** (`MapMarkers` gives each other player's dot a child label `.map-player-name`, a small dark pill above it).

- **Maps**: both draw one picture of the whole world, `WorldMap.Texture` (one pixel per block column, display only, nothing on the network). `WorldMap` reads the terrain from this machine's world (`WorldSync.World`) in tiles of 16 × 16 columns, nearest to the player first, within 1.5 ms per frame (a 512 × 512 world is read in a few frames), keeps it, and rereads a column on `World.BlockChanged`; plants come from `EcosystemSync.PlantShown` / `PlantHidden` / `PlantsCleared`. A tile is redrawn into the texture only when something in it changed (crowns overlapping from neighbouring tiles included), and the texture is uploaded at most ten times a second, so the maps cost nothing while nothing changes: they only move and scale the picture. Each column's top is read with water counted (`World.GetTopHeight`); water is drawn flat and darker the deeper it is (`BlockAtlas.WaterColour`). Colours come from the assets: blocks from `BlockAtlas.MapColour`, a plant (per model) or animal from the material of the part with the most upward-facing area, a crown's size from its meshes' bounds, so a new species needs no setting. Animals (`EcosystemSync.GetAnimalPositions`, only those near the player are known), other players (NGO's spawned player objects) and the player's arrow (`MapArrow`, drawn with `Painter2D`, colours from the USS properties `--arrow-fill` / `--arrow-outline`) are elements placed every frame by `MapMarkers`; their styles are in `Assets/UI/MapMarkers.uss`.
  - The **minimap** (`Minimap` + `Assets/UI/Minimap.uxml`) is a round window at the top right, north up, 64 blocks from centre to rim, with the player's coordinates below.
  - The **full-screen map** (`MapScreen` + `Assets/UI/Map.uxml`) opens and closes with M (Escape also closes it); it is looked up with `FindKeyOnCurrentKeyboardLayout("m")`, since on AZERTY M is the key QWERTY calls semicolon. While it is open the mouse is free (wheel: zoom around the pointer, from the whole world to 12 pixels per block; drag: move; Space: follow the player again; Tab: climate layer, terrain → temperature → humidity, drawn from `Geography` over the picture). **Species layers**: beside the map, the list of layers (`SpeciesPanel`, titled "Layers": three drop-down menus (`Foldout`, closed at first), "Plants (42)", "Animals (22)" and "Soil (NPK)", each species with its map colour, its name and how many there are in the whole world, each nutrient (Nitrogen, Phosphorus, Potassium) with its colour and its mean level over the land in % (`SpeciesCensus.SoilMeans`); a search field filters it and opens only the menus holding a match, each menu given back as the player left it once the search is cleared; while it has the focus the map's keys type into it, Escape leaving it first) chooses one species, whose density is laid over the map (element `map-species`, above the climate): one pixel per cell of 8 x 8 columns, transparent where there is none, magenta turning yellow toward the most crowded cell (`ClimateColours.DensityLayer`, square root of the share). It comes from a census (`SpeciesCensus`): `EcosystemSync.RequestCensus` every 2 s while the map is open and when the choice changes; the host takes it at once (`Ecosystem.PlantCounts` / `AnimalCounts` / `PlantDensity` / `AnimalDensity`, `Ecosystem.Census.cs`, read only, never during a step: `CensusTests`), a client asks the server (`Eco.CensusRequest`, at most one a second per player) and gets the counts and the grid back (`Eco.Census`, a byte per cell: 16 KB for a 1024 world, then the three mean soil levels). **Soil layers**: the "Soil (NPK)" menu lays one nutrient over the map the same way (`SpeciesCensus.Kind.Soil`, the nutrient as the species index; `Ecosystem.SoilLevels` averages the soil cells into census cells, a byte of level × 127.5, `MeanSoil` the land's mean), coloured from pale sand (0.4, the lowest capacity) to the nutrient's colour (1 and above) (`ClimateColours.SoilLayer` / `NutrientColour`: nitrogen green, phosphorus orange, potassium violet), the header giving its mean level, since a client only knows the animals near its player. Every player may see them. The legend now only shows you and the players, and the full-screen map draws no animal dots (`MapMarkers` gets no animal layer from `MapScreen`; the minimap still shows the animals near the player); the animals' colours are in the list. While the map is open the coordinates, temperature and humidity under the pointer are shown, the minimap and the IMGUI texts are hidden, and `PlayerController` keeps the player still (`MapScreen.HoldsInput`, also true on the frame the map closes so that its key does nothing else). Closing it captures the mouse again.
- The remaining on-screen text (the session info under the HUD banner when the mouse is free: role and port, the router, the admin keys) and the crosshair are still drawn with `OnGUI` for display only.
- The block texture atlas is built at runtime by `BlockAtlas` from the files in `Assets/Resources/Blocks` (see block types above); `Assets/Materials/Blocks.mat` only supplies the shader settings. Its shader is **`ECO/Blocks`** (`Assets/Shaders/Blocks.shader`): URP's Lit shader copied from the installed package with only its name and forward pass changed (`BlocksForwardPass.hlsl`, the parts marked "ECO"), so shadows, Forward+ (PC), Forward (Mobile) and SSAO behave as before; after a URP upgrade, copy `Lit.shader` / `LitForwardPass.hlsl` again and reapply them. The atlas's **alpha channel is the tint mask**, not transparency (grass top and the green band of its sides are 0, from their `_Tint.png` masks): those pixels are multiplied by the climate's grass colour, read from the global texture `_ClimateTint` (one pixel per geography cell, blended) that `ClimateTint` builds from `Geography` when a world appears (a mild colour before), saturated tropical green where it is hot and very wet (both above 0.6, fully at 0.8) and dark olive by the share of marsh in each cell (`Landscape.IsMarsh`; per column on the maps). `ClimateColours` holds the colours (grass, map layers, °C and % readings) shared with the maps, whose grass follows the climate too. The deferred (GBuffer) pass is URP's own and does not tint; neither pipeline uses deferred.
- **Sky light** (`SkyLight`, `Voxel.Core`, display only: worked out by each machine that draws the world, never on a batch-mode server, nothing sent or saved): every cell gets 0 to 15. Air with only air above it up to the top of the world is 15, so a shaft gets open sky all the way down; every other step (sideways, upwards, into or through water) loses one level; opaque blocks hold 0. Levels are kept per chunk, as a single value for a uniform chunk (open sky, deep rock). `VoxelWorld` builds it when a world is shown (about 150 ms for 512 × 512, 700 ms for 1024 × 1024), updates it from `World.BlockChanged` (`SkyLight.Update`, a few microseconds: light is taken away from what the change darkened, then flows back) and from chunks replaced wholesale (`UpdateChunk`, for the modified chunks a client receives), and remeshes the chunks whose levels changed. `SkyLightTests` check that updates always give what computing the world again gives. `ChunkMesher` writes it smooth into each vertex's colour (red: the mean of the four cells in front of the face around that corner, opaque ones left out; quads split along their brightest diagonal), and `ECO/Blocks` multiplies everything a face receives (sun, ambient) by a curve of it, down to `VoxelWorld.darkestSkyLight` (global `_DarkestSkyLight`, 0.02: underground is really dark). Things drawn with other shaders do not read it, except the players' bodies (`PlayerModel` shades its material with `VoxelWorld.SkyBrightnessAt`, the same curve); plants and animals stand under the sky anyway. Water uses the same shader (transparent), lit by the air in front of each face: dark in a cave.
- **Torches** (`Blocks.Torch` = 34, rules in `Torches`, light in `BlockLight`, both `Voxel.Core`, `TorchTests`; drawing `TorchViews`): every player is given 20 once (`PlayerState.ReceivedTorches`, `players.dat` format 8; players from before too), in the hotbar; more are crafted, 4 from 4 wood (see Crafting), and a torch taken down comes back to the bag. A torch is a block type with an orientation (`Torches.Standing`, or the side its support is on, `OnEast`… `OnNorth`): a right click with one in hand on the top of a block stands it there, on a side hangs it there (`Torches.TryOrient` from the aimed face; none under a block: "A torch goes on top of a block or on its side"), in open air only, and the server checks that what holds it is solid (`BlockEditRules`, `Torches.HasSupport`). It is neither solid nor opaque nor replaceable (`Blocks.IsPlaceable` and `IsBreakable` include it; players, animals, rays and arrows pass through it, `World.GetTopHeight` leaves it out, a plant cannot stand in its cell, no block is placed over it), weighs 0.1 kg instead of counting with the blocks, goes in a chest, and is taken down **by hand**, one hit with anything in hand (`ToolRules.ToBreak` gives `Items.None`, `MiningRules.HitsToBreak` 1; strikes and the aiming label see it through `VoxelRaycast.Cast(..., thin: true)`, which stops at a torch when the ray enters its box, `Torches.GetBox`). When the block holding torches is broken they fall: `WorldSync.TryBreak` removes them (`Torches.FindHeldBy`) and gives them to whoever broke it. **Block light** (`BlockLight`, display only like the sky light, worked out by every machine that draws the world, nothing sent or saved): a torch gives its cell `Blocks.TorchLight` = 14, one level less per step through cells that are not opaque; only chunks some light reaches keep levels; it is built when a world is shown from the modified chunks only (torches are never generated) and updated from `World.BlockChanged` and `UpdateChunk` the way `SkyLight` is (taken away, then flowing back from what kept its light and from the sources), which `TorchTests` checks against computing it again. `ChunkMesher` writes it into each vertex colour's green channel, smoothed like the sky light, and `ECO/Blocks` adds the surface's colour times a warm `TorchColour` times `TorchGlow` (bright by the torch, about a fifth less per block), so a dark cave lit by torches fades to black beyond about a dozen blocks; `VoxelWorld.SkyBrightnessAt` takes the brighter of the two curves for the players' bodies. Torches are not meshed: `TorchViews` (in `VoxelWorld`, from `BlockLight.Sources`, within 96 blocks of the camera) draws each as a stick, a dark head and a flickering flame, instanced, upright in the middle of its cell or leaning out from its support, with the unlit materials `TorchWood.mat`, `TorchHead.mat` and `TorchFlame.mat` (so they look lit by their own flame at night). Never generated, so no generator version change; with no torch the meshes are the same (`ChunkMesherTests` unchanged). Icon `Torch.png` (`ItemIconBuilder`), item in the Tools category, kind "Light".
- **Day and night** (`DayNight`, on its own object in the scene): the hour comes from the simulation's clock (`EcosystemSync.StepTime`, the last known step count carried on at the current speed, so every machine sees the same hour without a message of its own; `SimClock.MinutesAt`, a simulation starts on day 1 at 8:00). One game day is 144 steps, 24 real minutes at speed 1, and passes as fast as the simulation when an admin speeds it up. The scene's directional light is the sun from 6:00 to 20:00 (east, south at midday up to 60°, west, warmer near the horizon), then a faint bluish moon opposite; the sky's ambient probe, the reflections and the skybox's exposure (on a copy of the skybox material) fade with `DayNight.Daylight`, and the underwater fog too. Nights are dark on purpose. In the menu the scene's lighting is given back exactly. Nothing in the simulation depends on the hour.

## Working with the Unity Editor

The Editor is driven through the **MCP for Unity** package (`com.coplaydev.unity-mcp`, tools named `mcp__unityMCP__*`). It only works while the Editor has this project open and the MCP bridge is running; load the `unity-mcp-skill` skill before using it.

- After creating or editing a script, Unity recompiles and reloads the domain. Tool calls made during that window fail or return stale results, so confirm compilation finished and check `read_console` for errors before using the new type.
- `manage_components(action="add")` has failed to resolve a freshly compiled project script by name even after compilation succeeded. Fallback: `execute_code` with `Undo.AddComponent(go, type)`.
- Scene edits made through MCP are not persisted until `manage_scene(action="save")`.
- World sizes (`VoxelWorld.sizeInChunks`, `GameSession.worldSize`, `-worldsize`) are in **chunks**, not blocks. The scene's default is 64 × 8 × 64 chunks (1024 × 128 × 1024 blocks, the planned final size, chosen so that the biomes, about 256 blocks across, all show: a 512 world holds only two or three climate zones): a host is ready in about 5 s in the Editor (2 s of it meshing chunks). The balance runs above were done on 512 worlds (`new World(32, 8, 32)`), which take a quarter of the time. Passing a block count (128 per axis is two million chunks) freezes the Editor until it is killed.
- In the Editor, private fields of scene objects survive script reloads and entering Play mode, and **a `null` string comes back as an empty string**. Test unset strings with `string.IsNullOrEmpty`, not `== null` (this once made the host send an empty player id and start without a player).
- The console regularly shows a `NoSubscription` error from `generators.ai.unity.com` (Unity AI generators without a subscription). It is unrelated to project code.

## Conventions that are easy to get wrong

- **Language**: everything in the project is English — comments, log and exception messages, inspector headers and tooltips, the text shown to players (written in English in the code and UXML, translated at display by `Loc`: a new text needs its line in `fr.txt`), and asset names (the plant species are `Oak`, `Bush`, `Birch`, `Pine`, `Acacia`, `Poplar`, `TallGrass`, `DryGrass`, `Cactus`, `Reeds`, `JungleTree`, `Palm`, `Fern`, `Willow`, `Cypress`, `LilyPad`, the crops `Oat`, `Wheat`, `Beet`, `Carrot`, `Potato`, `Cabbage`, `Maize`, `Sunflower`, `Bean`, `Butternut`, `Rice`, `Mushroom`, `Strawberry`, `Tomato`, `Grapevine`, `Cotton`, `PricklyPear`, `AppleTree`, `CherryTree`, `LemonTree`, `OrangeTree`, `BananaTree`, `CacaoTree`, `CoffeeShrub`, `MangoTree`, `DatePalm`, the animals `Rabbit`, `Fox`, `Deer`, `Reindeer`, `Wolf`, `Bear`, `Gazelle`, `Jackal`, `SnowHare`, `Jerboa`, `Fish`, `Duck`, `Heron`, `Otter`, `Crow`, `Vulture`, `Sparrow`, `Tapir`, `Jaguar`, `Crocodile`, `Frog`, `Parrot`; a seed is displayed with its asset name). Renaming a species makes existing `ecosystem.dat` files fail to load (the save records species names).

- **Input**: active input handling is the new Input System only (`activeInputHandler: 1`). `UnityEngine.Input` (`Input.GetKey`, `Input.GetAxis`) throws at runtime; use `UnityEngine.InputSystem`.
- **Keyboard layout**: the target layout is AZERTY (ZQSD movement). Input System `Key` values are physical positions named after the QWERTY layout, so `Keyboard.current.wKey/aKey/sKey/dKey` is ZQSD on AZERTY. Do not use `zKey`/`qKey` for movement.
- `Assets/InputSystem_Actions.inputactions` is registered as the project-wide actions asset, but `PlayerController` currently polls `Keyboard.current` / `Mouse.current` directly and does not use it.
- **Rendering**: URP with two quality levels, `Mobile` and `PC`, each bound to its own pipeline asset and renderer in `Assets/Settings/` (PC: Forward+ with SSAO; Mobile: Forward). Rendering changes usually need to be applied to both. With the Standalone build target the Editor only offers `PC`; `Mobile` is for mobile platforms. **Both have a shadow normal bias of 0** (PC depth bias 0.1): a normal bias shrinks every face of the casters, which opened slits where blocks meet along an edge, and at a low sun the light through them drew long bright lines on the ground and lake beds; checked at 9:00, 13:00, 17:00 and sunset without shadow acne. Two-sided shadow casting did not help.
- **Assets**: every asset needs its `.meta` file committed alongside it; move or rename assets through Unity (or move the `.meta` with them) so GUID references survive. Binary assets are tracked with Git LFS and Unity YAML uses the `unityyamlmerge` driver (see `.gitattributes`).
